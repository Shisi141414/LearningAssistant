# 课堂笔记复用内部格式：来源快照与统一阅读

> 2026-11-12 · codex

本批将成功保存的课堂整理稿、手动笔记接入现有 `LearningSource / LearningState / LearningEntry`，复用同一覆盖校验、类型字典、条目排版、公式显示与概念名称关联。进入笔记页点击“统一文档”，可按类型/关键字阅读、展开原始转写与教材锚点、选择已固定的历史修订。旧段落视图继续负责文字编辑和标注。

## 开源复查与选择

按“直接使用 → 迁移 → 修改 → 自己写”检查：

- [BlockNote 源码](https://github.com/TypeCellOS/BlockNote)及[格式互通说明](https://www.blocknotejs.org/docs/foundations/supported-formats)：结构化 JSON 保留内容属性，HTML/Markdown 转换可能丢失信息。当前需要的是已有语义模型和转写来源的衔接，直接换用富文本编辑器不能代替这些来源约束，故本批直接复用项目已有模型、校验器和渲染器，不增加编辑器依赖。
- [BlockNote 社区讨论 #3307](https://github.com/TypeCellOS/BlockNote/discussions/3307)提出删除内容后仍保留评论锚点文字。它提示来源仅靠当前可变段落定位会失效；本项目选择同时保存原始文字、段落版本及教材锚点快照，链接到当前段落时注明可能已变更/删除。
- [Joplin 笔记历史设计](https://joplinapp.org/help/dev/spec/history/)采用差分以减少写入量，并说明重建历史的成本。本批借鉴“变化部分单独保存”的思路，使用段落级完整不可变快照和整篇编号清单；无需迁移其同步/差分引擎，也避免每次转写复制整堂课正文。这是适配设计，并未复制该项目代码。

## 存储和发布

追加迁移 16，不修改既有迁移：

- `note_learning_documents` 关联真实笔记，不伪造教材版本满足教材表外键。
- `note_learning_blocks` 保存单段来源、语义状态及原始转写/模型/时间/教材锚点快照；通过内容散列复用相同快照。正文和语义格式均使用现有共享类型。
- `note_learning_revisions` 保存固定整篇的标题、学科与段落快照编号清单。打开或“读取最新笔记”时固定一次，内容未变不生成重复修订。历史下拉展示这些整篇阅读快照，并非每次键入都产生整篇修订。
- `note_segments.organized_model` 记录之后成功整理的模型 ID。旧 AI 记录没有模型时显示“旧记录未保存模型”，不补造模型、不标成人工确认。

新段落、人工保存及 AI 成功发布，在同一个 SQLite 事务中保存业务段落和语义来源。AI 请求仍在事务外执行；请求期间发生人工编辑时，现有修订比较拒绝覆盖。语义快照保存失败，整理稿也回滚，原文和旧快照保留。首次读取旧笔记时按需补齐当前段落快照；升级前已经丢失的编辑历史无法补回。

来源 `raw_text` 在共享格式中表示“本条来源的原样内容”，对笔记是已保存的 `organized_text`；原始转写另存 `origin.raw_text`，二者不互相回填。空整理稿保持为空。`extraction=native` 表示直接读取已保存的字段；是否 AI 改写由条目 `analysis` 和 `origin` 表达。AI 内容为待核对，人工保存标为人工编辑；记录时间不是录音时间轴，不伪造音频起止时刻。旧有重点/疑问标注和知识证据表不变。

历史快照不随段落修改/删除而重写。删除整篇笔记后快照保留在数据库，当前没有归档恢复界面。每篇统一阅读最多 5000 段，前端每组显示 100 条；来源按全文顺序验证覆盖，不以分页结果当作完整文档。
