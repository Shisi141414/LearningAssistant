# 任务中的学习资料与应用路径

工作报告：codex · 2026-11-13

## 本批目标及复用依据

补齐 R4 的具体资料引用：任务可以引用教材、课堂笔记、习题和项目文档中的固定修订条目，填写需要掌握/在此应用/产出证据/待解决问题/验证理解及用途、验收办法；任务和资料可双向定位。保留引用时摘录，来源更新或删除不覆盖用途与历史内容。

调研 [Logseq 的块引用](https://github.com/logseq/docs/blob/master/pages/Block%20Reference.md)、[其社区关于名称与 UUID 定位的讨论](https://discuss.logseq.com/t/block-reference-to-allow-page-name-block-ref-name-not-just-uuid/2746)及 [W3C Web Annotation 的选择器](https://www.w3.org/TR/annotation-model/)。引用条目需要稳定身份；仅靠正文偏移容易受修改影响。采用现有条目 ID + 固定修订 + 引用时摘录，不根据相同标题或相似文本擅自重定位。本批直接复用内部格式、公式/图片显示、已有来源读取与项目/日程模型；不迁移整个 Logseq 应用或增加通用图数据库，不复制外部实现。

## 实施与验收约束

- 只追加迁移；关联表有任务和各来源修订的真实外键，来源删除后保留摘录并明确不可导航，不把原 ID 误连到别的来源。
- 保存前验证来源实体、修订、条目确实匹配；重复添加不覆盖已填写的用途；修改/移除检查关联修订标识。
- 项目任务与手动日程复用同一关联；从四类来源进入任务，从任务返回引用时条目。来源页显示使用它的任务；列表按需读取，避免每个课堂条目自动发请求。
- 验证旧库升级回滚、关联保留、跨实体/修订拒绝、原文变化/删除、去重、陈旧操作、任务级联隔离、真实页面往返和重启。随后运行类型检查、构建及完整回归。

## 已接通的使用流程

1. 先在项目或日程中建立任务。
2. 在材料的统一学习条目、课堂笔记统一视图、习题的题面/解答分区，或项目文档条目中展开“用于任务”。可以按任务/项目名称查找，选择已有任务。
3. 填写资料用途（需要掌握、在此应用、产出证据、待解决问题、验证理解）、可选的知识点、“为什么需要、如何应用”和“怎样验证理解”。保存时引用当前所见的固定修订。
4. 从资料下方的使用任务跳转到项目任务或日程编辑区。任务的“学习与资料”中可阅读摘录，编辑用途与验证方法、移除关联，或打开引用时条目。项目看板展开资料的分组使用整行宽度；日程仍保留同一任务与时间块。

知识页的“学习与应用”同时读取任务原有知识引用和这些资料关联，按任务去重；新增关联不改写原任务的知识 JSON。链接中的资料修订与任务关联自身的修订是两回事：前者确定“引用的是什么”，后者用于拒绝多个窗口互相覆盖。

材料、笔记和项目文档超过100条时，来源跳转会定位到目标所在分页并突出该条目。笔记、习题与项目文档新增固定修订导航；无法读取指定修订时显示错误，不自动替换为最新版。课堂的实时跟随默认行为保持原样，只有从固定引用进入的笔记视图读取指定历史版本。

## 数据与失败行为

- migration 025 仅追加 `task_resource_links`；任务删除级联清除自身关联。材料/笔记/习题/项目文档修订有真实外键，笔记还绑定其活跃笔记实体。来源被真正移除后保留引用文字及其用途，链接显示不可用。材料归档、习题与文档回收站仍可读历史来源。
- 摘录、公式范围、图片引用/附件元数据和课堂原始转写在关联时保存；来源更新不会覆盖它们。图片复用既有附件存储，不额外复制图片文件；若附件被真正清除，显示无法读取并提示对照原件，不声称仍有图像备份。
- 同一任务与同一来源实体、修订、条目唯一；再次添加返回原关联，不覆盖说明。保存前验证实体/修订/条目属于同一份资料。关联修改和移除都检查原关联修订；冲突会保留填写草稿，刷新前有放弃修改确认。
- 保存使用数据库事务；失败不留半条记录，可重试。资料用途变化不触碰任务状态、截止时间、计划时间和提醒。
- 单个任务最多64处关联；列表每次读取50项，支持继续读取。单条摘录最多40000字符，关联原始转写最多200000字符，用途和验证方法各4000字符；过长明确拒绝并请先拆分。长度均按 JavaScript UTF-16 长度计。
- 来源侧按需展开后才读取关联任务；阅读课堂条目不会为每条来源自动发请求。收起任务资料保留本页填写状态；离开页面的草稿不作为已保存内容持久化。
