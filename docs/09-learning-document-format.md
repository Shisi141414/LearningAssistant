# 统一学习文档格式草案

> 2026-11-11 · 设计与报告：codex · 状态：0.1 草案；格式约定与示例已落地，应用尚未接入语义拆分、图像提取和统一排版。

## 1. 用户目标与核心决定

所有受支持的课件、讲义、教材导入后，保留原件，再转换为统一的学习文档。内容按一般叙述、定义、定理、命题、证明、解答、配图等条目储存、检索和显示，归属学科；课堂、知识库与项目引用同一批稳定条目。

采用“原件 → 带来源的结构内容 → 学习语义条目 → 检索与阅读”的分层流程。**文件转换解决能否读取，语义整理解决内容是什么，两者分开。** DOC/PPT 可以先用成熟工具转换；扫描件经过 OCR；已有可用文字时直接提取，避免额外识别损失。

内部格式采用公开 JSON 数据结构和独立附件，不自创二进制编码。格式标识为 `learning-assistant/document`，草案版本 `0.1`。暂不固定专属扩展名。未来可用标准 ZIP 携带 `document.json`、`source/` 原件和 `assets/` 图片等附件；本轮没有实现打包、导入或导出入口。

## 2. 开源复查与复用边界

按“直接使用 → 迁移 → 修改 → 自己写”评估：

| 方案 | 已有能力与证据 | 本项目决定 |
|---|---|---|
| [DoclingDocument](https://docling-project.github.io/docling/concepts/docling_document/) / [docling-core](https://github.com/docling-project/docling-core) | 文本、表格、图片、层级、位置与来源信息 | 优先作为复杂 PDF、图表、OCR 的候选适配器；需先用中文力学/数学样例验证质量、运行体积与性能，不立即引入 Python/模型运行环境 |
| [Docling 标签](https://github.com/docling-project/docling-core/blob/main/docling_core/types/doc/labels.py)与[自定义元数据讨论](https://github.com/docling-project/docling-core/issues/544) | 通用版面类型和扩展元数据 | 版面结构复用；定义/定理/证明等学科语义作为扩展层，避免把图片、标题与学习概念混为一种标签 |
| [BlockNote 文档结构](https://www.blocknotejs.org/docs/foundations/document-structure) | 稳定块 ID、嵌套块、富文本/表格与图片 | 作为后续编辑器候选；编辑器数据不是来源与引用的唯一依据，不因更换编辑器而重建条目 ID |
| [Pandoc 读入—AST—写出架构](https://pandoc.org/using-the-pandoc-api.html) | 输入与输出通过中间结构解耦 | 采用适配层思想；不把 Pandoc 当扫描 PDF 的 OCR 工具 |
| 已集成 OfficeParser / PDF.js | DOCX/PPTX 结构提取、PDF 文字与原页预览 | 首批继续直接使用，补充语义层；旧格式转换遵循 [R2 转换调研](08-classroom-material-link.md)，优先调用 LibreOffice，不移植庞大格式解析代码 |

社区的[行内公式讨论](https://github.com/docling-project/docling/discussions/894)说明正文中的公式也需要独立表达。我们的内容节点区分文本、公式、附件和表格，不能把所有公式压平后再猜回来。上述资料支持候选能力，不代表本项目已验证识图或公式识别效果。

## 3. 数据约定

可检查的 [JSON Schema](formats/learning-document-0.1.schema.json) 与 [演示文档](formats/learning-document-0.1.example.json) 是本草案的具体样本。演示原件/图片路径与散列为占位，不附真实文件，不能作为已导入材料或文件完整性证据。

| 层 | 保存内容 | 关键约束 |
|---|---|---|
| 原件 `original` | 文件名、媒体类型、SHA-256、包内引用 | 不用 AI 输出替换原件；格式转换生成派生文件，保留原件与转换记录 |
| 来源 `source_units` | 稳定 ID、原始提取文字、页/幻灯片/逻辑段落及可用区域 | 原始提取文字也可能有 OCR 错误；位置不够精确就按页或段落标明，不能伪称精确框 |
| 条目 `entries` | 稳定 ID、语义类型、标题、内容节点、章节父节点、来源范围、整理记录 | 一个条目可跨页；一页可含多个条目；重排不改变 ID |
| 关系 `relations` | 证明→定理、解答→题目、图片→正文、依赖与引用 | 类型独立于章节层级；不靠相邻顺序猜归属；未确定的关系留待审核 |
| 附件 `assets` | 本地相对路径、媒体类型、散列、来源 | 图片正文关联与图片说明分开；没有提取出的图不能用 AI 凭空补出 |

类型首先覆盖：章节、叙述、定义、定理、命题、引理、推论、证明、例题、习题、解答、配图、表格、公式、注意。定理与命题分别标记，不能沿用现有笔记 `proposition` 类型把两者合并。定义/定理内部可以同时包含文字、行内公式和配图。

来源文字范围使用 JavaScript/JSON 所在应用的 **UTF-16 编码单元**、左闭右开 `[start,end)`；由程序计算，不让模型估算中文字数。图像来源可以不带文字范围。来源单元另可记录现有 `material_blocks` ID 作为迁移映射。

`parent_id` 仅表示章节/结构容纳；`proves`、`solves`、`illustrates`、`depends_on`、`refers_to` 表示知识关系。例如一个证明与定理处于同一章节，通过 `proves` 关联，不必把证明硬塞进定理正文。

数据库接入时，以 **SQLite 中已提交的文档修订及关系为工作数据权威**；JSON/ZIP 是可验证的交换快照，避免磁盘 JSON 与数据库同时独立修改产生冲突。发布修订不可原地覆盖，人工调整生成下一修订。原件仍由托管文件系统保存。此处是后续实现决定，本轮没有新增数据库表。

## 4. AI 的职责与校验

先从解析器获得有序内容单元，规则识别“定义 2.1”“证明”等明确标记，AI 辅助处理隐含边界、跨页续接、类型和归属。规则与模型推断都带来源、方法和待审核状态；模型记录供应商/模型标识，不能将模型自报置信度当成准确率。

模型接收稳定单元 ID 和程序生成的行/片段标识，返回边界及类型建议。程序解析建议后计算实际范围，拒绝不存在的 ID、越界范围、遗漏正文或重复覆盖；对跨块/重叠检索片段不能直接拼接为全文。当前 `chunkText` 的重叠片段只是检索/上下文单元，**不是语义条目边界**，需要在分块前保留规范化的来源序列。

来源文字与 AI 改写分开。未能识别的内容保存为待整理的叙述；失败、取消或无模型时仍能保留原件和提取结果，不假装完成语义分类。用户可以拆分、合并、改类型和修正归属；修正过的条目不可被重试结果无条件覆盖。AI 补充的解释另存为有标记的注解，不能作为教材原文。

长书采用可恢复的小批任务、有限上下文和相邻结构信息；导入先保存，不让完整书籍整理阻塞课堂。云模型整理由明确入口启动，显示使用的模型、范围和进度；OCR 与版面解析可独立使用本地工具。

JSON Schema 只校验字段结构。接入时还必须验证：ID 唯一与引用存在、父节点无环、关系方向及类型相容、文字范围不越界、内容覆盖情况、文件散列与路径范围。不能把“JSON 合法”当成“教材完整正确”。

## 5. 统一排版与检索

内容存“类型”，主题存“颜色/字体”，不把样式写死到每条数据。初始学习正文采用宋体；定理/定义等标题用黑体；证明/解答可用楷体；公式继续交给数学排版器。字体不可用时明确回退到系统中文字体。导航等界面文字沿用应用主题。

各类型使用独立的颜色标记、文字类型标签和边线；正文保持可读的深色，不能只凭颜色区分。提供标准、紧凑与原件对照阅读方式，先实现一种标准布局再扩展。

检索单位是语义条目，可按学科、文档、类型、章节和关键字筛选。命中定理时可展开其证明、相关图和应用；打开条目能回到原件来源。全文关键词检索先交付，向量检索在确有需要时再选型。学习条目是来源组织，知识点是跨文档概念，两者多对多，不默认每条叙述都变成知识点。

## 6. 建设顺序与验收

1. **本批：格式草案与样本。** 明确结构、关系、来源、原件与修订边界；Schema 自检和示例结构验证。尚无运行时语义文档功能。
2. **下一批：语义文档基础闭环。** 从已支持的 PDF/DOCX/PPTX 导入生成来源序列和条目草稿；保存文档修订，支持人工改类型/拆分/合并、统一阅读与按类型检索。新增迁移时保留现有版本、块和所有课堂引用；不能通过重建旧块来“升级格式”。
3. **AI 拆分与关系建议。** 接入显式启动、后台任务、校验、审核与冲突保护。测试同页多个类型、定理/证明跨页、例题/解答分离、无显式标题、含 emoji 的来源范围、模型漏段/幻觉/失败恢复。
4. **复杂输入与图文。** 对中文数学/力学教材实测 Docling 等候选，再接 OCR、图片/公式/表格提取及旧 DOC/PPT 转换；保存转换链与质量标记，禁止把普通文字提取标成识图完成。
5. **复用到知识和项目。** 用稳定条目 ID 将课堂记录、知识点和项目任务连起来。AI 重整理、换教材版本后，旧引用仍能打开当时内容。

先用短讲义完成闭环，再验收整本教材。质量验收需人工对照原件检查内容覆盖、公式准确性、图文顺序和关系正确性；单靠技术测试无法证明教材语义无误。

## 7. 本批检查

使用本机已有 `jsonschema` 校验 Draft 2020-12 Schema 本身和演示文档；检查样例的 ID 唯一、父节点无环、来源/附件/条目关系存在，以及全部来源单元均被引用。负例确认未知类型、越界包路径、AI 缺少模型标识会被结构校验拒绝；检查了本地文档链接与 Git 差异空白。

这些检查仅针对草案和样例，不是运行时导入器，也不验证不存在的演示原件/图片散列。本批不改运行时代码和数据库；此前 R2 的完整测试证据见 [课堂联动记录](08-classroom-material-link.md)。
