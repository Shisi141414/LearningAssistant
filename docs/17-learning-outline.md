# 学习文档章节层级

> 2026-11-12 · 设计与报告：codex · 手工章节层级首批交付

## 复查与方案

复查 [Docling 的文档树](https://github.com/docling-project/docling/blob/main/docs/concepts/docling_document.md)、[单一父节点的层级设计讨论](https://github.com/docling-project/docling-core/issues/19) 与 [BlockNote 嵌套块结构](https://github.com/TypeCellOS/BlockNote/blob/main/packages/core/src/pm-nodes/README.md)。采用稳定 ID 加单一父章节的表示，直接复用现有有序条目与不可变修订，不引入完整编辑器或重建来源顺序。通用嵌套编辑器不能直接保证本项目的来源精确覆盖、历史引用及人工整理保护；本批只补层级约束与阅读/归属交互，不迁移通用编辑器。

## 数据与编辑边界

条目增加可选 `parent_id`，缺省或 null 为顶层。仅章节可作父节点，父节点必须在条目前面；章节最多六层，同章子树在来源顺序中连续，禁止循环、跨越已结束章节或丢失子节点。旧修订按原有顶层条目读取，不批量改写历史；层级随新修订保存，不另建可与正文矛盾的目录文件。

人工选择连续条目范围及父章节，整体调整这片范围的根节点，内部子章节保持。范围必须包含所选章节的完整子树，父节点不能在范围内。归属修改不改变原文、来源和语义确认状态。把有子项的章节改为普通类型前须移出子项；合并须同父章节且不能吞掉带子项的章节。普通条目拆分继承父章节；章节标题拆分出的正文归入该章节。

AI 分类仍只处理同一父章节内的待整理条目，新候选继承原父章节；不让模型重写人工目录，也不自动推测章节级别。涉及跨章节或会遗失子项的范围拒绝。知识证据继续固定原修订；章节调整不迁移旧证据。

## 界面与验证

保持学习阅读的宋体正文、黑体标题、楷体证明；背景 #f7f7f5、正文 #1f2328、辅助 #6b7280、边线 #e5e5e0、操作 #4f46e5。在现有阅读工具栏附近增加折叠目录与章节筛选；条目前显示可点击的章节路径。编辑条目时按“父章节 + 范围结束条目 → 保存章节归属”明确操作，不用拖拽暗中改变来源顺序。目录点选清除筛选并定位正确的一组 100 条；历史目录只读但仍可导航。

验收旧快照兼容、无环/六层/连续子树、范围归属与失败不发布、拆分/合并/改类型保护、AI 单章继承和跨章拒绝、来源与关系不变、证据历史稳定、目录跨分页定位、按章筛选、历史查看和重启保留；相关回归、类型检查、构建及 1024 宽界面检查。

## 使用方法与交付边界

材料库 → 学习文档 → 整理条目，先把标题条目设为“章节”并保存；从其后第一条打开整理，在“章节归属”中选父章节及范围结束条目，保存后生成新修订。可在折叠目录跳到章节、按章筛选（包含子章节），或通过条目上方路径回到父章节。父章节只提供该位置仍开放的章节，保持教材顺序；若所选范围截断已有子树，保存会提示扩展范围，文档不变。

本批不推断标题级别，也不自动建立目录。旧修订、原件和已确认的证据仍固定原样；`parent_id` 只写入新的修订快照，不需要改写已发布数据库迁移。关系可以跨章节，章节层级不能代替证明或知识引用。

新增六项逻辑回归覆盖兼容、非法层级、范围调整、拆分/合并保护、AI 父节点继承和持久化/历史证据。真实 Electron 集成以 104 个来源切分条目跨越两组，走界面保存范围、二级章节筛选、类型联合筛选、目录跨组及重复定位，检查 1024 宽无横向溢出，并在关闭应用后重新启动核对层级、旧修订和证据散列。模拟来源用于交互与数据约束验收，不能证明真实教材的章节识别质量。
