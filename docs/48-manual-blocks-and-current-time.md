# 学习时间块手动调整与当前时间跟随

日期：2026-11-14 · codex

## 使用

日程的日/周视图中，可拖动**尚未开始且未锁定的学习时间块**，或拖动上下边缘调整时长；月视图可移动到其他日期。拖动先回到原位，再打开待确认窗口，不立即写入。固定课程和截止标记不可拖动。也可从任务编辑 → 学习安排 → **调整时间**填写起止时间，已锁定的未来块可用此入口明确修改。已开始、已完成任务及归档项目的块不能移动。

点击“检查时间调整”，核对固定日程、其他任务及同一任务其他块的重合时间；区间首尾相接不算重合。有冲突时必须主动勾选“忽略冲突”才可确认。截止、最早开始、可用时段、前后置安排、时长变化和学习块间缓冲不足显示警告，人工调整可在了解警告后保留。这不是完整的可行性求解或学习完成证明。

确认后仅更新该块，保留稳定 ID、任务截止时间及剩余用时，并**锁定**新位置，持续排程据此安排其他块；解锁后允许自动重排。时长变化不会自动推断实际学习进度。取消或检查失败不改变安排，失败时保留输入。相同起止时间不产生空历史，也不改变锁定状态。

调整沿用最近 20 次排程历史，展示移出/移入、用户手动来源、理由及警告；最近一次可撤销，成功撤销在同一事务中暂停持续排程。历史保留、旧预览失效和撤销限制沿用[持续排程](47-continuous-schedule.md)，不是无限审计存储。

## 时间轴跟随当前时间

日/周视图包含今天时，进入视图会滚动到当前时间前约一小时，尽量显示后续日程。例如 21:00 时红线仍在框内，时间轴末尾的 24:00 边界可见；滚动受日末及视图高度约束。月视图、未包含今天的日/周保持设置的起点。

每 30 秒及窗口重新获得焦点时检查当前时间；红线本身沿用 FullCalendar 的分钟级刷新。红线接近下方或离开可见区时重新定位。日历高度根据窗口和底部快捷栏适配，必要时滚动外层页面，避免红线仅在内部滚动框可见而被实际窗口裁掉。手动滚动或按下鼠标后暂缓 30 秒，拖动和时间块确认窗口期间暂缓，不在拖动途中抢动滚动条。若当前时间早于 6:00 或自定义起点，今天临时展开到当前小时以保留红线；未修改用户保存的起点设置。

## 开源选型与写入保护

直接使用已安装的 MIT 许可 FullCalendar 6.1.21 interaction 插件，不增加拖动库、不升级到文档当前主版本：

- [v6 eventDrop](https://github.com/fullcalendar/fullcalendar-docs/blob/main/_docs-v6/event-dragging-resizing/eventDrop.md)、[eventResize](https://github.com/fullcalendar/fullcalendar-docs/blob/main/_docs-v6/event-dragging-resizing/eventResize.md)：使用移动后时间与 `revert()`，先还原暂态再确认数据库写入。
- [社区 #5441](https://github.com/fullcalendar/fullcalendar/issues/5441)：查看持久化事件变更入口的讨论，本批只在用户确认路径写入，避免把程序更新产生的事件变化再次保存。
- [scrollTime](https://fullcalendar.io/docs/scrollTime) 与 [scrollToTime](https://fullcalendar.io/docs/scrollToTime)：直接复用现有滚动 API，应用自行决定今天跟随与临时手动浏览的时机。

按“直接使用 → 迁移 → 修改 → 自己写”复用现有日历、时间冲突扫描、排程快照、SQLite 事务及撤销；自行实现项目特有确认和时钟跟随策略。无需数据库迁移或新依赖。

确认指纹绑定数据库路径、完整任务/块/设置/依赖快照、原块修订、新起止时间、冲突与警告。保存时在事务内重新核对，期间任何变化拒绝旧同意，必须重新检查。块更新、变更序列与历史同事务提交，故障回滚全部内容。原块 ID 保留，因此已有导出 UID 和导入去重身份不变；提醒服务会按新块修订失效旧计划。
