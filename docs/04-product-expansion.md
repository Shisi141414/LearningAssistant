# 项目、日程、备忘与教材课堂联动

> 版本：v0.2 · 日期：2026-11-11 · 整理：codex
>
> 来源：用户本次新增需求。本文是待实现的产品规格，不表示下列功能已经可用；阶段安排见 [路线图](03-roadmap.md)，现有问题见 [体检报告](05-health-check-2026-11-11.md)。

## 1. 统一的学习闭环

学习材料 → 课堂记录 → 知识条目 → 项目中的实际应用 → 问题与复习。

项目、日程和备忘共用知识与来源引用，避免形成三个互不相通的资料孤岛。学科负责知识归属；项目可以跨学科；活动继续表示单场讲座、会议或讨论，不与项目合并。

例如：“制作一个振动测量装置”项目引用力学中的简谐振动、代数中的特征值和程序设计中的采样处理。助理从项目任务反向找到要学的概念、教材位置、已有笔记和练习，并把项目中学到的经验链接回这些知识。

## 2. 项目系统

### 2.1 用户可以做什么

- 创建、编辑、归档项目；记录目标、项目要求、交付物、约束、完成标准和相关学科。
- 保存计划书和项目文档，记录修订版本，关联已有笔记、材料、知识点、备忘和对话。
- 拆分里程碑与任务，设置开始时间、截止时间、依赖、优先级、预计用时和状态；区分任务负责人备注与应用的本地单用户身份。
- 查看当前进度、下一步、阻塞原因、临近截止时间和已完成的成果。进度由任务与里程碑支撑，助理说明计算依据，允许手动调整。
- 让助理根据要求起草计划、分解任务、检查遗漏、建议调整日程，并给出每条建议的依据。

### 2.2 如何帮助学以致用

任务与知识点建立有方向、有语义的关系：`需要掌握`、`在此应用`、`产出证据`、`待解决问题`。同一个知识点可服务多个项目，关联不复制知识正文。

项目任务卡显示“为什么需要这个知识 → 到哪里学习 → 本任务怎样应用 → 怎样验证理解”，并链接到材料原位、课堂段落、习题或项目成果。助理可以识别知识缺口，生成学习任务并纳入日程；用户修正关联后保留修正。

### 2.3 验收样例

创建一个跨学科项目，导入要求和计划书，建立两个里程碑与三个任务。给一个任务关联已有知识点和一段课堂笔记；从任务能打开来源，从知识点能找到应用它的项目。修改截止时间只修改同一任务，日程与提醒随之更新；归档项目保留资料和历史。

## 3. 日程、自动排程与提醒

### 3.1 统一任务来源

支持手动任务、项目任务、备忘识别出的待办、作业以及未来的复习任务。它们进入同一任务系统，保留来源，避免项目页、日程页和作业页各造一份待办。

区分三件事：截止时间是必须完成的时刻；日程时间块是计划什么时候做；提醒是何时通知。改动时间块不应偷改截止时间。固定上课、会议和用户锁定的时间块优先保留。

### 3.2 自动管理

- 用户设置可用时段、每日负荷、免打扰时间、提醒提前量及自动排程范围。
- 助理结合截止时间、优先级、预计用时、任务依赖和可用时段安排任务；大任务可拆成多段，预留缓冲。
- 在已启用的自动管理范围内，自动安排和调整未锁定的任务，记录调整理由与变更历史，支持撤销；信息不足或约束冲突时列出待处理事项。
- 支持完成、延期、取消、稍后提醒和逾期处理。外部作业同步后按来源 ID 去重，用户编辑字段的覆盖规则单独记录。

### 3.3 提醒的可靠性

提醒计划与投递状态持久化；用“任务 + 提醒时间 + 渠道”生成去重标识。启动和从休眠恢复时检查错过的提醒，在用户设置的补发窗口内合并补发。任务完成或截止时间改变后，旧提醒失效。

首期使用应用内提醒与 Windows 本地通知。应用完全退出后，普通内存计时器不能继续执行；需要常驻后台或系统调度才能兑现退出后的提醒。是否启用常驻、开机启动及系统通知权限，应在设置中明确展示。未启用后台能力时显示实际提醒范围。邮件、短信及外部日历同步另列扩展，不把它们当作本期已有能力。

### 3.4 验收样例

给定一个固定课程时间块和两个有截止时间的任务，系统能安排无冲突的工作时段，并解释安排。锁定其中一个时段后重排保持它不动。完成任务不再提醒；更改截止时间后旧提醒不再触发；重启和休眠恢复后不重复通知，冲突和无法排入的任务明确可见。

## 4. 备忘：随手记与自动归档

### 4.1 录入与识别

提供全局快速入口，先立即保存原文，再异步识别。支持知识点、事实/重要事项、任务、日程、项目想法和混合条目；一条备忘可同时产生知识引用与任务。

例如：“周五交振动实验报告，记得用傅里叶变换检查频谱”：识别为任务，并提取“傅里叶变换”知识关联。原始备忘一直保留，展示识别结果、目标位置和处理状态。

### 4.2 自动进入已有系统

- 明确的知识内容自动关联已有知识点或创建待完善知识条目；优先检索和去重，避免重复概念。
- 明确的待办和时间自动形成任务/日程与提醒；保存识别时的时区、相对时间解释基准和日期解析结果。
- 分类与目标足够明确时，在用户启用的规则内自动归档并显示可撤销结果；低置信度、日期冲突、学科不明的条目进入待整理箱，不擅自猜出一个重要截止时间。
- “周五”“下次课前”等相对时间随输入时间与课程日历解释；缺少必要信息时标记待补全。
- 离线仍可随手记录和手动分类，联网后补处理。识别失败可重试；重试不重复建任务；修改原文后能追踪和更新衍生条目。

### 4.3 与灵感库的关系

现有灵感库保留，作为“项目想法/创造性记录”的一种视图或关联目标；将来扩展为统一捕获入口时，迁移已有内容并保留 ID 与来源，不能直接改名后丢掉旧数据。

### 4.4 验收样例

分别记录纯知识、纯待办、混合条目和一个时间不明确的备忘；验证自动归类、复用已有知识、任务去重、原文保留、撤销、离线补处理和用户修正。撤销自动归档不删除其他条目正在引用的共享知识。

## 5. 课件、讲义、教材的导入与条目化

### 5.1 格式与内容

文件格式和材料用途分开：同一个 PDF 可以是课件、讲义或教材。按学科管理，也可被多个项目、课程或活动引用。

| 输入 | 首期要求 | 原位定位 |
|------|----------|----------|
| PDF | 文本 PDF；扫描 PDF 走 OCR；混合文档逐页判断 | 文件版本 + PDF 物理页 + 页面区域 |
| Word `.docx` | 标题、段落、表格、公式、图片和可用的语义结构 | 文件版本 + 稳定块 ID；预览转换映射另存 |
| PowerPoint `.pptx` | 幻灯片顺序、标题、文本框、图片、表格和备注；复杂对象标记待处理 | 文件版本 + 幻灯片 + 对象/区域 |
| 旧版 Word `.doc` / PPT `.ppt` | 纳入支持范围，经独立转换适配器转为规范格式后走同一管线；转换依赖和安装方式实施前验证 | 保留原件，存转换版本及原件映射 |

不能解析的文件明确显示原因和处理办法；不能只接受扩展名就宣称支持。首个导入版本可先交付 PDF、DOCX、PPTX；旧格式转换作为紧接的独立验收项，整体格式需求不删减。密码文档、损坏文件、超大文件和转换缺失有可见失败状态。

### 5.2 处理流水线

选择文件与学科 → 保存原件及文件指纹 → 扫描/提取与必要的 OCR → 按章节、页、段落、幻灯片生成内置材料条目 → 建立学科内检索与引用。

每个条目保留所属材料及版本、章节路径、页/幻灯片/块位置、原始提取文本、整理文本、公式/图片引用、解析质量与处理状态。AI 整理不能取代原始提取内容；识别不确定的公式和图表需要可回看原件。

导入是可查看进度、可取消、可重试的后台任务，大文件/OCR/转换不阻塞课堂 ASR。重复文件先识别；教材换版或重新解析产生新版本，不能让旧笔记链接悄悄指向新内容。

解析器通过适配器统一输出“有来源位置的块”。现有 `chunkText()` 仅输出正文与标题链，存在顺序与长度缺陷；修正并扩展后才能复用，不能当作已完成的文档导入器。具体解析/OCR/转换依赖在实施时做样例验证与选型记录，本次不安装。

### 5.3 验收样例

为同一学科导入课件、讲义、教材，覆盖文本 PDF、扫描 PDF、DOCX、PPTX 及旧格式转换。抽查标题、页序、表格、公式与图片；搜索条目能回到原始位置。重复导入可去重；取消和失败后可恢复；重解析或换版后，已有课堂引用仍能打开原版本。

### 5.4 统一学习文档（2026-11-11 补充）

所有受支持材料保留原件，转换为应用内统一结构；按叙述、定义、定理、命题、证明、例题、解答、配图等语义条目存储与检索。条目可跨页，保留来源范围；证明归属定理、解答归属题目、图片关联正文。学科和章节管理与跨文档知识点关系分开。

类型控制统一颜色和字体，正文以宋体为默认，标题/证明等按主题选黑体/楷体，配文字标签而非只靠颜色。AI 辅助拆分和识别，保留原始提取内容、模型记录与人工审核；失败或不确定进入待整理，不能默默删段、改写原文。人工拆分、合并、改类型与关系可追踪。

开放数据结构、原件/附件约定、复用决策与分批验收见 [格式草案](09-learning-document-format.md)。当前仅完成设计、Schema 与样例；语义存储、分类、图片提取和统一排版仍需后续接入。

自动关联补充：同一定理或方法的已确认不同名称对应稳定概念 ID，正文提及自动链接到概念；同名多义结合学科保留候选。不同教材中的原始条目、证明和适用条件不能因别名归一而丢失。概念层首版已接入现有文字材料和笔记/课堂，完整语义导入及 AI 别名发现仍待实现，见 [关联交付记录](10-concept-alias-links.md)。

## 6. 左教材、右转写的课堂

### 6.1 课前与课中操作

- 课前选择本讲的主教材/课件，可附加讲义；设置本讲开始点（章节、页、幻灯片或条目）。恢复上一讲位置只是建议，用户可改。
- 上课左半屏显示材料阅读器，右半屏显示实时转写与整理记录；分栏可调。原文/整理切换继续保留。
- 课中实时显示“当前讲到的位置”。用户可点击某页、某块或“从这里继续”立即校准；支持老师跳页、回讲、切换材料和暂停自动跟随。
- 从右侧笔记点击来源定位左侧材料；从左侧材料能查到对应课堂片段。段落跨多处内容时支持多个来源，不强行一段只对应一页。

### 6.2 自动对齐与教材辅助整理

初期先做可靠的人工校准，再加自动对齐。用课前起点或最近一次人工校准作为搜索锚点，结合当前转写、临近材料条目、标题/术语和可用上下文，估计讲授位置。

优先在当前附近检索，但允许全局跳转候选。低置信度显示“位置待校准”，不强行翻页；用户校准优先，保存校准事件及时间，后续推断从新位置开始。历史段落保存当时的锚点快照，不能在每次移动当前页时改写全部旧引用。

整理时注入当前附近的教材条目，辅助纠正学科术语、符号与公式。严格区分“老师说了什么”与“教材补充了什么”：原始转写不可覆盖；补充信息带材料引用；二者冲突时显式标出，不为了贴近教材而篡改讲授内容。

### 6.3 验收样例

从教材第 3 章指定块开始课堂，确认左右分屏与起点恢复。模拟正常推进、跳页、回讲和切换材料；每次人工校准都应立即生效。选一段转写可以跳回其当时教材位置，反向也能找到记录；重启后仍可定位。自动对齐不确定时给出待校准状态；离线时仍可阅读、转写和手动链接。

## 7. 建议的数据边界（设计草案，尚未迁移）

| 领域 | 建议实体/关系 | 关键约束 |
|------|---------------|----------|
| 项目 | `projects`、`project_documents`、`milestones`、`project_subjects` | 项目跨学科，文档可追踪版本 |
| 任务/日程 | `tasks`、`task_dependencies`、`schedule_blocks`、`reminders` | 统一任务 ID；截止与安排分离；投递去重 |
| 备忘 | `memos`、分类运行记录、归档动作与产物关系 | 先存原文；幂等；能撤销和修正 |
| 材料 | 扩展 `materials`，新增 `material_versions`、`material_blocks`、`import_jobs` | 原件保留；稳定 ID；版本和位置可追溯 |
| 课堂位置 | `classroom_sessions`、`material_cursor_events`、段落与材料锚点关系 | 起点、人工校准、自动估计、历史快照分开 |
| 知识应用 | 知识点与项目/任务/来源的显式关联表 | 多对多；有关系类型；有外键和失效策略 |

尽量采用有外键约束的关联表；共享引用协议可先统一为“实体类型 + ID + 可选版本与位置”，但不把所有实体塞进一个无法验证外键的 JSON 字段。现有 `ContextRef` 可增量扩展；引用展开仍由主进程完成。

现有 `assignments`、`review_records` 与 `inspirations` 不直接删除。先设计它们向统一任务/备忘体系的映射和迁移，再执行；业务代码、IPC 类型、界面与迁移按同一功能批次交付。

## 8. 实施顺序与学习要点

建议按 [路线图](03-roadmap.md) 的 R0–R6 逐步交付：先修可靠性问题，再做带位置的材料条目与人工课堂联动，然后做知识关联、项目、日程、备忘自动分流和更智能的对齐。

材料条目的稳定定位是课堂联动的前提；统一任务模型是项目截止时间、日程和备忘自动安排不互相打架的前提；可追溯的知识引用是项目中应用所学知识的前提。这些基础比先堆四个独立页面更决定系统后续能否协同工作。
