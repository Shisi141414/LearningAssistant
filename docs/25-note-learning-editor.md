# 笔记结构编辑与来源同步保护

> 2026-11-12 · codex

接续 [笔记格式首批](24-note-learning-format.md)，笔记统一文档现在可编辑语义类型和标题、拆分/合并、章节范围、证明/解答归属及人工公式校正。与教材共用 `LearningOperation`、`changeLearningState`、覆盖校验、`LearningEntryEditor` 和公式编辑器，不再各写一套语义编辑逻辑。历史修订只读；跨来源合并后显示所有原始转写和教材位置，不只显示第一段。

## 开源路线复查

按“直接使用 → 迁移 → 修改 → 自己写”复查：

- [ProseMirror transform 源码与说明](https://github.com/ProseMirror/prosemirror-transform)及[官方变换指南源码](https://github.com/ProseMirror/website/blob/master/markdown/guide/transform.md)：不可变文档、变换和位置映射是成熟的编辑器方法。该 GitHub 仓库已迁移，链接主要用于核对既有设计；当前入口见其 README。项目没有 ProseMirror 树，直接引入会额外维护第二种文档模型，故本批直接复用已有类型化操作/不可变修订，只新增笔记的持久化适配。
- [ProseMirror 社区关于替换节点后位置失效的讨论](https://discuss.prosemirror.net/t/mapping-positions-in-deleted-nodes/5000)明确指出整节点替换不能期望旧内部位置依然有效。本项目据此不猜测改写后的公式/拆分偏移：正文完全相同才重连来源 ID，否则完整重建受影响来源范围，并保护人工结构。
- [Tiptap UniqueID](https://tiptap.dev/docs/editor/extensions/functionality/uniqueid)核对稳定节点标识的方案。当前已有来源、条目和修订 ID；沿用这些编号，不引入富文本节点或重编号已有数据。变化范围重新建立的条目不能冒用旧定理 ID，以免旧证明悄悄指向新的叙述。

这些是设计参考，没有复制第三方源代码，也未新增依赖。

## 修订与升级

追加迁移 17，只给 `note_learning_revisions` 增加可空 `state_json`。迁移 16 的旧修订仍按原段落快照清单重建；编辑后保存整篇语义状态，来源正文继续由不可变段落快照提供。原始转写、段落编辑、标注、知识证据和教材锚点不因结构编辑而改写。数据库升级及失败回滚均保留旧记录。

所有修改由主进程以“笔记 + 预期修订 + 条目”执行共享变更并校验覆盖，再原子保存新修订。禁止使用其他笔记的修订、伪造字段或旧修订覆盖新状态。笔记尚无附件适配，配图修改不开放；材料的配图编辑继续通过原接口工作。

## 如何接入后续课堂变化

课堂每段仍独立保存，避免每次转写生成全篇内容。读取最新文档时比较来源清单：

1. 尚未进行语义编辑的笔记直接按当前段落生成新修订。
2. 已整理笔记新增段落时自动追加，保留已有条目 ID、公式和关系；新段落沿用插入位置尚未结束的章节。
3. 同一段落的整理正文完全一致时，仅更新来源 ID/原始转写等来源信息；原拆分范围、公式、标题及归属保留。
4. 正文更新、移除、重排，或在跨段合并条目的内部插入来源时，完整重建受影响范围。共享一个来源的拆分条目、跨多个来源的合并条目一起计算闭包，确保全文恰好覆盖一次。
5. 未受影响的条目保留。失效的证明/解答关联明确解除；消失或已结束的父章节回退到有效祖先。影响人工结构、公式或归属时，不自动发布，当前修订保持原样。

用户可查看新增/更新/移除段落、旧新正文、条目类型/标题、将解除的关系和将移除的公式校正，并复制原 LaTeX。关闭预览不改当前语义文档；确认后才保存新修订，旧修订继续可读。预览和确认同时核对当前修订 ID 与来源清单/标题/学科散列；预览后新增转写、再次整理或结构变化，会拒绝旧确认并要求重新预览。预览与发布的重建条目 ID 确定一致。

不会尝试用字符串差分推断公式位置或语义等价。即使只是改几个字，也可能改变定理含义；保留来源和可核对的变化范围，比无依据地保留旧证明归属更可靠。
