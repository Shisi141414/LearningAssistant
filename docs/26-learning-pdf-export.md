# 教材与笔记的固定修订 PDF 导出

> 2026-11-12 · 设计、构建与验收：codex

教材学习文档与笔记“统一文档”现在共用 PDF 导出入口。选定修订后展开“导出 PDF”，选择 A4 纵向或横向、是否附来源文字，再选择保存位置。导出包含该修订的全部条目，不受阅读页的搜索、类型、章节或每组 100 条限制。保存期间锁定本页修订操作，可取消排版；未保存的编辑需先保存。

## 开源选择

按“直接使用 → 迁移 → 修改 → 自己写”比较：

- 直接使用 [Electron webContents.printToPDF](https://www.electronjs.org/docs/latest/api/web-contents) 和 [PrintToPDFOptions](https://www.electronjs.org/docs/latest/api/structures/print-to-pdf-options)，由应用已经携带的 Chromium 排版。参考其 [GitHub API 文档源码](https://github.com/electron/electron/blob/main/docs/api/web-contents.md)，无需新依赖。复用现有 React、KaTeX、本地字体及受管图片读取；只增加打印页面和业务适配。
- [PDFKit](https://github.com/foliojs/pdfkit) 可直接生成 PDF，但需要重新实现中文流式排版、数学公式转图或矢量排版、条目分段、链接等，形成第二套显示逻辑，本批不引入。
- [BlockNote 的 PDF 导出](https://www.blocknotejs.org/docs/features/export/pdf) 基于其编辑器文档模型。当前项目已有来源范围、语义条目和不可变修订，不为导出迁移整套编辑器模型。
- [Electron 社区关于 Windows 打印页眉页脚的复现](https://github.com/electron/electron/issues/40714)涉及旧版本普通打印，不等同于本项目版本的 PDF 缺陷；它提示需要验证实际纸张输出。[社区关于重复页眉/分页的讨论](https://www.reddit.com/r/electronjs/comments/1rw24mr/need_help_with_reliable_repeated_headers_and_page/)也说明固定定位和手工切页不应当作通用方案。本批用浏览器自然分页和原生页脚，并检查实际导出坐标、页码和渲染图片。

未复制第三方实现，也没有新增运行时依赖。复用不等于直接截屏：课堂界面有工具栏、折叠和分页，打印必须从固定数据构建专门页面。

## 排版与来源

- 正文宋体，标题黑体，证明/解答楷体；类型颜色与阅读界面一致。导出嵌入实际使用的字体子集，不依赖接收方安装字体。
- 复用 `MarkdownSegment` 和 `LearningFormulaContent` 的文本/数学节点，打印时关闭交互式概念按钮。显式公式校正继续保留原文范围；公式不能覆盖来源文字。
- 目录、证明/解答对象和来源附录使用 PDF 内部链接；导出书签与带标签的文档结构，但不宣称 PDF/UA 或 PDF/A 合规。
- 证明等长条目自然跨页，不能给整篇正文加固定高度、隐藏溢出或“整条不可分页”。图片保持比例，最大尺寸受纸张限制，图注随图片一起排版。
- 字体载入后按公式实际宽度适配。缩放后低于约 8pt 时拒绝导出并指明条目，建议横向或人工分行；没有实现自动数学断行。初次验收发现 KaTeX 显示公式外层块宽不代表实际宽度，已修正打印样式并覆盖普通缩放与过宽拒绝。
- 来源位置始终保留。勾选原文时，教材附来源文字，笔记附原始转写及不同的保存整理稿；笔记默认勾选，教材默认不勾选。记录时间不冒充录音时间轴；教材引用为当时的锚点。
- 只输出当前条目已经关联的图片。扫描来源尚无文字时，保存前和保存结果都说明空来源数量，PDF 中标明缺失；不会在导出时自动 OCR，也不会把原件所有页面直接拼进重新排版的文档。

## 固定版本与保存边界

`LearningPdfInput` 只接受材料版本或笔记 ID、明确修订 ID 和两个选项。主进程从数据库事务读取来源/条目/公式/关系/来源证据，历史笔记读取不会触发新来源同步。笔记标题随修订固定；材料标题、文件名和学科名称沿用材料当前元数据，正文仍是所选不可变修订。

打印使用独立的隐藏窗口、非持久会话、无 preload、无 Node 能力。数据经主进程注入，React 转义文本；CSP 限制脚本、字体和图片。打印会话只开放本次关联的托管图片，读取时继续验证路径、容量和 SHA；不共享或改写课堂窗口麦克风权限。图片全部解码、字体就绪、宽度检查通过后才调用打印。

仅系统保存框指定路径，拒绝覆盖应用数据目录及指向托管数据的链接；与文档包共用此校验。一次只允许一个 PDF 作业，取消限发起窗口；关闭发起窗口或退出应用会取消未提交的作业。载入、排版、打印各有 180 秒上限。工作计数阻止导出时迁移数据目录。

先在目标旁创建独占临时目录，以独占方式写文件并刷盘，成功后原子替换目标。普通失败、取消会销毁窗口并清理本次临时文件，已有目标不动。替换进入提交点后不再报告取消成功。突然断电可能留下尚未提交的临时目录；不跨目录扫描删除用户文件。本批未增加数据库迁移。

## 验收

常规检查：`npm run typecheck`、`npm run build`、`npm test`。可单独运行 `npm run test:pdf`；该命令构建后启动真实 Electron/主进程/preload/Chromium，用隔离数据目录和测试保存框生成 PDF，再由 PDF.js 解析、检查并渲染。

- 4 组新增逻辑检查：固定笔记修订及原始转写、非法 IPC/取消参数、空笔记与保存框取消、受管目录和已有目标保护。全部逻辑检查合计 115 项。
- 120 条中文笔记，包含 100 行跨页证明、公式、后续人工修订和新来源变化；41 页。验证 120 个唯一正文标记均存在，旧修订没有混入后加内容；122 个内部链接，原始转写与来源可查。
- 教材合成样例含目录、长公式、配图与来源，纵向 2 页、横向 3 页；验证图片 SHA、缩放、宋体嵌入、带标签结构/书签、所有页码以及文字坐标在纸张内。首页、中间/末页和横向配图页已渲染检查。
- 保存框取消、托管路径拒绝、并发导出拒绝、正在排版时取消、图片损坏、超宽公式均验证失败保护，原有目标保持字节不变，普通失败不留下临时目录。打印会话未改写主窗口媒体权限。
- 实际笔记阅读页点击 PDF 选项和保存按钮，验证生成有效 PDF 并恢复修订选择操作。
- 完整回归发现原笔记 UI 脚本在点击展开后立即访问尚未提交的公式框。点击操作现明确等待下一绘制帧，并检查按钮可操作，失败时显示具体表达式；原结构、公式、来源同步和重启断言全部保留。

| 353 页工程热力学扫描 PDF | 353 / 1 | 50 | 此修订 353 个来源均未 OCR；输出来源位置和已绑定选区图，绝不代表整书正文已经识别 |

## 继续方向

后续 [课堂实时批次](27-classroom-learning-format.md) 已接通统一文档阅读及导出期间的新来源保护；笔记 AI 结构候选、笔记文档包交换、自动数学/图文识别仍待建设。项目系统、日程提醒、备忘分流及知识实体合并继续按路线图分批推进，不因本批 PDF 导出而标记为完成。

从编程角度，可把流程理解为四个有边界的步骤：数据库选定版本 → 共用模型生成打印页面 → 浏览器排版为字节 → 原子保存。这样排版失败不会污染数据，后续换排版引擎也无需改变笔记和教材的存储格式。
