# 语义条目首批：来源、边界与人工分类

> 2026-11-11 · 设计与报告：codex · 实施前方案，验证结果在交付后追加

## 本批范围与复用选择

实现 PDF / DOCX / PPTX 的规范来源序列、人工类型/标题、拆分/合并、证明/解答归属、统一排版与类型检索。已存在的检索块带重叠，不能用拼接它们的方法恢复来源全文。直接复用 OfficeParser / PDF.js 从不可变原件取得来源；OCR/校正版 PDF 按已保存的页级识别/人工校正覆盖对应页的来源文字，不重新 OCR。

再次检查 [BlockNote 的稳定块 ID 与结构](https://www.blocknotejs.org/docs/foundations/document-structure)、[ProseMirror schema/不可变节点](https://prosemirror.net/docs/guide/)和 [Tiptap Node views](https://tiptap.dev/docs/editor/extensions/custom-extensions/node-views)。它们是后续自由富文本编辑器候选；本批直接复用现有 React/KaTeX/概念渲染及原生只读文本选择，不构造自有富文本编辑器。新增部分仅为学习类型、来源覆盖和修订关系这些业务约束。

[W3C Text Position Selector](https://www.w3.org/TR/annotation-model/#text-position-selector)提供位置选择器参考；本应用内部明确采用 UTF-16 左闭右开范围，与既有格式草案一致，不把它直接宣称为 W3C 的 Unicode 字符计数。记录来源 ID 与范围，且拒绝在代理对内部拆分。

## 数据与修改原则

- 来源按页/幻灯片/逻辑结构保留完整文字，在检索切块前捕获；空白页保留空来源，不能把“尚未提取文字”的提示伪装成教材正文。
- 每个材料版本可建立一个学习文档。首次建立在后台重取来源并原子入库；重复点击共用任务。已建立后不重解析、不改变来源 ID。应用退出终止准备，未提交结果可重新建立；原件、旧材料块和课堂引用不变。
- 首批最多 1000 个来源单元、总计 200 万 UTF-16 单元、5000 个语义条目。超限明确失败，不能静默截断。
- 初版全部标为“待整理的叙述”，不以固定长度或页面边界宣称已经完成语义识别。人工可按光标拆分，同页不同类型；相邻条目可合并，跨页来源仍分别保留。
- 条目 ID 与修订 ID 分开：更改类型/标题或拆分保留左条目 ID；合并保留前条目 ID。每次提交新修订，旧修订只读可查看；修改必须携带当前修订 ID，拒绝陈旧编辑覆盖。
- 全部来源文字在当前修订恰好覆盖一次，不漏段、不重叠，不接受不存在或越界的来源。文字来源只读；OCR 文字校正走上一批的校正版流程。后续 AI 输出必须通过相同校验，不能覆盖人工修订。
- 证明通过 `proves` 指向定理/命题/引理/推论，解答通过 `solves` 指向例题/习题。关系与排版顺序分开，不能因相邻而假定归属。有关系的条目合并前须先解除关系，避免静默改指向。
- SQLite 中保存不可变来源和已提交修订；仍未交付完整 0.1 JSON/ZIP 交换器、结构章节层级、配图/公式提取或 AI 自动拆分。

## 实施前界面计划

继续材料库阅读页，增加“来源检索 / 学习文档”切换，采用纸面阅读方式：底色 #f7f7f5、正文 #1f2328、辅助 #6b7280、边框 #e5e5e0、操作 #4f46e5。宋体正文，黑体类型标题，证明/解答楷体；颜色只用于类型文字和左边线，不染整段正文。每条同时显示中文类型标签，兼顾不能分辨颜色的使用者。

布局：`[修订选择 / 类型筛选 / 搜索] → [类型与标题] [来源页链接] → 正文 → [整理条目]`。整理表单包含类型、标题、只读来源文字（用鼠标/键盘放置拆分光标）、“在光标处拆分”、相邻合并及证明/解答目标。来源链接打开相应 PDF 原页或已有材料定位；历史修订隐藏修改操作。首屏明确“待整理”，避免把初始页面分段当作 AI 结果。

审视方案后保留材料库既有布局，仅用类型标签、边线和字体表达学科内容关系；不增加无关统计卡片或新的装饰系统。配图等类型本批只标注现有文字来源，不意味着提取出了图像。

## 验收计划

同页拆为定理/证明、跨页合并、类型过滤与统一显示、证明/解答目标方向、代理对边界、来源覆盖、陈旧修订拒绝、历史修订和课堂引用保留、旧版本从原件补来源、OCR 校正文继承、应用重启。实际界面操作与本地真实材料均使用隔离目录；不上传私密教材。

## 交付与验证

迁移 v9 追加来源、文档与修订表，旧版材料/OCR/课堂记录保持原状。按需在后台建立来源，OfficeParser 使用 `document-structure` 且表格使用 `flatten`：源码确认普通 `row` 检索模式会在多个片段重复表头，不能作为来源正文。PDF 在文字检索切块前捕获页文字；已保存的 OCR 与人工校正按页覆盖规范来源。原始 OCR 审计字段仍独立保留。

入口位于材料库“学习文档”。来源文字只读，人工调整类型、标题、边界和证明/解答关联；首版按宋体正文、黑体标题及楷体证明/解答排版，带中文类型和颜色标记。类型筛选、标题/正文搜索、PDF 原页对照、历史修订查看与当前修订刷新均已接通。初始条目仍明确显示待整理。

- 31 项逻辑测试涵盖 v8→v9 升级保留 OCR/课堂引用、UTF-16 代理对边界、同页拆分、跨页合并、重新合并不添换行、来源遗漏/重复/越界拒绝、关系方向、陈旧修改拒绝与历史修订保留。
- 真实 Electron 界面测试完成：建立来源、鼠标放置拆分光标、类型/标题保存、定理与证明归属、过滤、概念自动关联、历史只读、1024 宽界面与重启后持久化；并发建立共用同一来源任务，归档材料拒绝新建。
- 实际材料：353 页扫描 PDF 保留 353 个来源（未识别页为空）；转换后课件保留 53 页 / 436 个来源；实验讲义得到 80 个来源。文字检索、来源 ID 重复读取稳定、原件散列不变。旧 DOC/PPT 的应用内转换仍未实现。
- OCR 集成再次通过，校正版正文进入学习文档时标为人工来源；真实热力学教材第 26–27 页标为 OCR 来源；已建立来源和原课堂引用跨应用关闭/启动保留。

界面验收还复现并修复了结束课堂后立即切换页面被异步结束操作拉回课堂的问题：结束操作完成后同时核对页面是否仍挂载、地址是否仍是发起时页面，再更新课堂地址。仅检查卸载标记不足以覆盖地址已改变但 React 尚未卸载的窗口。现在立即离开后不会被旧操作改写导航。

本批是统一格式的可用来源/人工整理基础，未交付 AI 自动分类、自由富文本修改、章节容纳关系、图像/公式提取和完整 JSON/ZIP 交换。下一批在同一覆盖与修订校验上加入可审核的 AI 拆分建议，不允许覆盖已确认的人工结果。
