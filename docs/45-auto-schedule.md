# 自动安排学习时间（首批）

日期：2026-11-13 · codex

## 使用与实际边界

1. 在日程页新建任务，填写截止时间并保存。项目任务也可从项目详情的“安排学习时间”进入。
2. 展开日程编辑下方的“学习安排”，填写**剩余**用时、优先级、最早开始、可否分段、分段长度及前置任务，启用并保存。有固定开始时间的任务须先清除固定时间。
3. 展开日历上方的“自动安排学习时间”，设置时区、每周可用时段、每日自动安排分钟上限及缓冲。样例可用时段是每日 19:00–21:00，请按实际课程修改。
4. 选择最多 31 天的日期范围，生成预览。核对将替换的原安排、新时间段、未安排原因及警告，再确认应用。取消预览不改动日历。
5. 点击日历时间块编辑同一任务，在“学习安排”中锁定、解锁或移除某段。停用自动安排保留已生成的时间块。改回固定日程前须移除所有时间块并停用。
6. “撤销最近排程”恢复该次排程前的时间块。任务、设置或时间块已被修改，或受影响时间已开始时拒绝撤销，保护后续修改。最多保留 20 次记录，当前界面提供按顺序撤销最近一次。

时间块与任务截止时间分开存储。多个时间块仍引用同一个任务，学习资料、地点、完成状态和项目归属不复制；改变安排不会更改截止时间。完成任务后对应块不再占用可用时段，可勾选显示已完成查看。

每日上限统计自动学习时间块；固定课程会占用可用时段，但不计入此上限。过去的时间不自动当作已完成；用户应更新“剩余用时”。运行中的保留块只扣除其尚未结束的部分，补充分段用时向上取整至 5 分钟。小于最少分段长度的整个短任务允许单段安排。

这是 **R5 的首批约束排程闭环**，不是整个 R5 完成：当前由用户生成预览并确认应用；任务变化触发持续自动调整、直接拖动时间块、完整历史列表、持久提醒/免打扰/休眠补发、应用退出后提醒、FSRS 和作业来源仍待构建。

## 开源与社区选择

- [Taskcheck](https://github.com/00sapo/taskcheck)：工作时段、日历避让、依赖、用时、dry-run 和撤销构成有用参考。其数据源是 Taskwarrior，属于单独的 Python 任务系统；本项目已有统一任务和 SQLite，不直接安装或迁移整套系统，也未复制其源码。
- [OR-Tools 官方 Job Shop 示例](https://developers.google.com/optimization/scheduling/job_shop)：前置关系和不重叠应作为硬约束，而非 AI 提示词。首批规模有界且必须在现有桌面环境工作，暂不引入额外求解器运行时；以后若简单策略频繁漏掉可行排程，可用相同输入输出契约替换规划器。
- [Super Productivity 社区日历导出讨论 #3957](https://github.com/super-productivity/super-productivity/issues/3957)：检索到的需求与时间跟踪到日历的导出有关，作为时间段互通的补充参考，不作为算法正确性证据。
- 直接复用现有 FullCalendar、ICS 解析/导出、冲突检查及 `@js-temporal/polyfill`；没有新增第三方依赖。每周可用时段及排程日期范围使用明确时区；预览、日历和任务编辑按本机时间显示。31 天按自然日期计算，不误拒绝跨夏令时的 31 天加一小时范围。夏令时不存在或歧义的时段拒绝自动进位并在预览解释。

顺序仍为“直接使用 → 迁移 → 修改 → 自己写”：日历/时间/ICS 直接使用，现有任务与冲突服务扩展，本项目约束调度和事务适配自行实现；采用确定性的截止优先启发式，不宣称最优或一定能找到所有可行安排。

## 设计与保护

追加迁移 **26**：`task_planning` 保存选用范围和用时，`task_dependencies` 为真实外键，`schedule_blocks` 保存独立分段，`schedule_settings` 保存时区/可用时段，`schedule_runs` 保存可撤销快照。未修改既有迁移和原任务时间字段。

- 仅处理用户启用的 open/doing 任务和 active 项目；固定时间、锁定、已开始、范围外及未启用任务的时间块保留。
- 前置依赖先拓扑就绪；前置任务继承后继的最近截止时间，再按截止、优先级、稳定 ID 分配。固定前置须在固定时间段结束后，完成的前置立即满足。循环或不存在的依赖拒绝保存。
- 从可用时段减去已有占用与缓冲，再分段。不能完整安排某任务的剩余时间时回滚该任务的暂定分段，并阻止依赖它的后继；在预览解释。原有可重排块可能因此列入“将替换的原安排”，须用户确认后才移除。
- 已保留块可能因后续改期而违反截止或依赖。不会偷偷移走，预览列出问题；已有重叠和超出每日上限也列出警告。
- 排程在 worker 计算，20 秒超时、窗口取消和退出可终止，不占用课堂主进程做排程运算。上限为五千任务、五百配置、一万时间块。
- 预览绑定窗口与数据目录，10 分钟有效；应用在事务内重新核对全部任务、设置、依赖、块的指纹。任务改动、切换数据目录或开始时间已过去均拒绝旧预览。失败整批回滚，不留下部分时间块或撤销记录。
- 配置和时间块操作使用独立修订号。陈旧输入不覆盖新数据，界面保留草稿供复制或刷新。
- 新建/编辑日程及课表导入的冲突检查包含学习时间块，原来的“忽略冲突”仍需明确选择。日历颜色和地点延用任务分类。
- ICS 导出每段的实际起止时间，另保留任务截止；本机再次导入按块标识去重。已移除块保留导入墓碑，避免旧导出文件把它复活。其他电脑可将各段导为固定日程；跨电脑不恢复自动排程配置和依赖。
