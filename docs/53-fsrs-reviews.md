# 知识点与习题的 FSRS 复习（2026-11-14）

署名：codex。属于 M4 的复习闭环；网络学堂作业同步、导学助手、小组件仍另行构建。

## 使用与评分

从知识点或习题详情点击“加入复习”，会保存已保存内容的固定版本并打开复习页。同一来源重复加入会打开既有条目，不重置记忆。知识点应先有释义；习题应先有标准答案或解题思路。习题保留整个内部学习格式、来源、公式和配图引用，不另造题目格式。

复习页有“今日与逾期”“全部条目”“暂停与不可用”及学科筛选，每页 50 项。今日清单包括本地今天稍后到期的条目，只有已经到时的条目可开始评分；每三十秒刷新清单。先根据题面或概念名称回忆，再“显示答案”，查看释义、思路、标准答案、原用户答案和错因。看答案前的记忆情况决定评分：

| 评分 | 含义 |
|---|---|
| 忘记 | 未能回忆，或答案错误 |
| 困难 | 回忆成功，但费力 |
| 记得 | 正常回忆成功 |
| 轻松 | 很容易、准确地回忆成功 |

显示答案后会预览四档下次时间，评分使用主进程收到评分时的实际时间重新计算。默认目标保持率 90%，不是个人记忆效果保证。短期再学可能在一分钟后到期；不要把“困难”用来代替“忘记”。评分仅更新记忆模型，**不修改习题用户答案、对错或原始版本**。完成一题后可选择“下一条到期”。

每个条目只有一条关联任务；评分只改其建议复习时间，不添加重复任务。日程与提醒沿用现有统一任务和持久提醒管线，支持从日程或提醒进入复习。复习初始设置为到点提醒，避免分钟级再学沿用普通任务提前一小时的默认值；可在日程详情中调整该任务的提醒选项。复习条目不允许通用日程编辑、任务完成或删除绕过评分；暂停/恢复在复习页进行，暂停保留原到期时间与全部历史。

误评分可撤销最近一次评分，恢复其前的完整模型状态和到期时间。后续评分、暂停、内容更新等操作会使旧撤销失效，避免撤销覆盖后续决定。撤销后的旧请求重试也不会重新应用那次评分。

## 开源复查与取舍

按直接使用 → 迁移 → 修改 → 自己写比较后，直接使用 [ts-fsrs](https://github.com/open-spaced-repetition/ts-fsrs) **6.0.0**（MIT），并锁定依赖。它直接提供调度、学习步进、四档预览和复习日志，无需迁移另一种语言的算法或自己写遗忘曲线。[官方更新与迁移说明](https://open-spaced-repetition.github.io/ts-fsrs/updates/)明确 v6 采用新 API、默认 FSRS-7，不能照搬旧 `fsrs()/createEmptyCard` 示例。

依据[官方快速开始](https://open-spaced-repetition.github.io/ts-fsrs/guide/quick-start)与 [DefaultScheduler](https://open-spaced-repetition.github.io/ts-fsrs/api/ts-fsrs/default-scheduler)，明确使用 FSRS-7、保持率 0.9、学习步进 1/10 分钟、再学 10 分钟、不开随机扰动、最大间隔 36500 天；FSRS-7 默认可根据模型结果覆盖学习步进，因此不承诺“记得”一定只排到十分钟。模型参数使用库自带默认值，未训练个人参数，未安装额外原生优化器。

社区复查包含[学习步进跳过问题 #311](https://github.com/open-spaced-repetition/ts-fsrs/issues/311)：历史版本曾有步进行为问题，因此本项目不根据旧截图硬编码时间，而用新版本公开 API 验证四档结果，覆盖 New/Learning、到期/迟到复习与撤销。项目自写部分仅为来源快照、界面、事务、幂等凭证及统一任务联接。

v6 要求 Node 24+；项目开发环境要求相应调整为 `>=24.22.1 <25 || >=26.12.1`，Electron 自带 Node 24.22.2 已满足。当前命令行 Node 24.21.0 低于项目和 OfficeParser 要求的补丁版本，安装会提示警告；构建与桌面验收结果据实记录，不声称宿主已升级。

## 数据、并发与来源保护

只追加 migration 032，既有 v1–v31 原文不修改。`review_cards` 保存固定来源版本、完整快照、记忆状态、算法/策略版本、建议时间与唯一任务；`review_logs` 记录评分和管理操作、前状态、来源快照及库返回的复习日志；`review_attempts` 保存“已显示答案”的限时评分凭证。库模型保留 FSRS-7 的 `stabilityFast` 等完整字段，不用自写简化状态替代。

为保留既有任务的 CHECK 约束、其他功能的外键与迁移历史，任务底层仍使用独立任务行，**`review_cards.task_id` 唯一关联是来源判别的依据**；任务、提醒接口明确返回 `review_id`，日程复习颜色按来源学科分配。标题和学科作为受事务维护的摘要列，清单与日历不读取、反复解析整份习题快照；学科删除只解除当前分类，原固定快照保留。不能仅凭标题将普通任务伪装成复习。

加入、评分、撤销、暂停、来源更新及关联任务的变化在同一 SQLite 事务发布。任一步失败回滚记忆状态、日志与凭证；不会有“已评分但日程未更新”的半成品。主进程核对修订、启用状态、来源可用性、实际到期时间与系统时钟，不信任前端传入时间或间隔。只允许显示答案后三十分钟内评分；重新显示会使旧的未提交凭证失效。重复同一凭证/同档评分返回已保存结果，不再次计数；不同档重复提交拒绝。同条目新评分和页面切换都会使较早请求失效，迟到的读取或操作响应不得覆盖刚保存的评分或替换新选中的条目。

来源修改时不覆盖正在复习的固定版本，显示版本变化提示；明确“采用最新内容”才更新快照，记忆进度保留。旧评分始终保留当时来源。原习题回收/恢复、知识点删除通过数据库触发器同步任务状态并使旧评分凭证失效；来源不可用时保留快照和历史，停止日程提醒，恢复来源后可继续。

早期 `review_records` 表保留原样；来源和算法版本不明的旧 JSON 不擅自当作 FSRS-7 状态转换。界面显示旧记录数量，来源仍可重新加入当前复习库。不同算法/策略版本不兼容时拒绝写入，留待有依据的迁移，不重置用户记忆。
