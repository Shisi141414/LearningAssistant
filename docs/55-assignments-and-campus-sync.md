1. 手动作业与统一任务：复用原 `assignments`，追加唯一任务映射、编辑修订、回收恢复和审计；旧作业升级不丢失原值。支持按学科/未完成/逾期/回收站管理，标题、要求、截止和本地状态可编辑；日程/规划器/提醒使用同一任务。作业页和日程互相定位，学习资料继续用已有任务关联。通过升级失败回滚/重试、陈旧编辑、删除不再占用时间、恢复不复活旧锁、源关联与重启验收。
2. 学校连接与同步：在官方窗口登录，只读获取学期/课程/作业；课程映射学科，预览后确认，来源键包括连接/课程/学生作业编号。源数据原样留版本，按字段保留人工覆盖；上游截止/提交状态变化列出差异，重复同步不复制，回收站条目不因同步复活。部分课程失败不误删任务；取消、过期会话、断网和重启有明确结果。学校“已提交”与本地“已完成”分开，不代交作业。
3. 持续同步：在上述链路通过后，追加明确启用、刷新范围、重试/离线补处理和停用取消，复用现有任务排程/提醒，不静默扩大登录授权。

## EPIPE 修复的复验与使用

此工具只用于开发验收，不代表作业同步界面已经交付。临时验收入口及独立安装的库仍在忽略目录，后续需重做前置测试时可运行：

```powershell
node scripts/launch-electron-background.cjs out-tmp/learn-probe.cjs
```

该命令输出本次进程编号和日志位置；日志在忽略的 `out-tmp/electron-background-*/runtime.log`。验收程序仍直接将去敏统计写到 `out-tmp/learn-probe-status.json`。不要把私人响应、密码、Cookie 或令牌写进日志。已完成的登录无需为了验证启动器再次登录。

回归检查 `scripts/electron-background.test.mjs` 使用真实 Electron 和隔离目录，先等待启动器退出，再写控制台、标准输出、标准错误及最终状态；应无 EPIPE，日志和状态都保留。另验证入口或可执行文件缺失时明确启动失败，不能留下伪成功记录。仅清理测试自己启动的进程。
