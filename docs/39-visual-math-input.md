# 在输入区直接编辑公式

工作报告：codex · 2026-11-13

## 问题和交付

此前数学面板把 LaTeX 字符串插入 textarea/input，只有多行输入框外另设预览；单行快捷栏没有预览。因此选择分式或希腊字母后，输入框仍显示代码。

现在共享 MathInput 使用同一输入区混排正文和可视化公式，覆盖课堂手动记录、对话、底部快捷栏和灵感输入。点击 ∑ 选择符号或模板，会在当前光标/选区插入可编辑公式；分式等模板将光标移入占位格。公式内继续点符号可在当前公式中插入，箭头或 Tab 可退出公式；公式内 Enter 先返回正文，避免误发消息。中文输入法的确认事件不触发外层发送快捷键。

直接输入单行完整 `$...$` / `$$...$$` 会转为公式，粘贴还支持跨行公式与 math 代码块；未闭合内容继续作为可编辑文本；代码、转义美元符保持文字。灵感保存后的列表也使用现有公式阅读组件显示，避免保存后重新暴露代码。

## 开源选择

先检索 GitHub 和社区中的可视化数学编辑器，再核对官方文档、React 19 兼容声明和已安装包：

- 直接使用 [Tiptap / ProseMirror](https://github.com/ueberdosis/tiptap) 3.33.1（MIT）的正文、段落、换行、历史、选区和粘贴能力；只启用本批需要的扩展，不将原始 Markdown 自动改成其他排版。
- 直接使用 [MathLive](https://github.com/arnog/mathlive) 0.111.4（MIT）处理公式排版、分式/上下标编辑和数学光标；[官方集成说明](https://cortexjs.io/mathfield/guides/integration/)和[交互说明](https://cortexjs.io/mathfield/guides/interacting/)提供 MathfieldElement 的输入/插入接口。
- 通过 Tiptap 自定义公式节点连接两者，节点视图保存 MathLive 的可编辑元素。没有自行编写数学布局、分式光标引擎或文本撤销栈。
- 调研 [Tiptap Mathematics](https://tiptap.dev/docs/editor/extensions/nodes/mathematics) 后未直接安装：该版本 KaTeX peer 范围不包含本仓库 0.19，且默认点击后仍需自行接编辑界面。保留既有阅读渲染器，为本批编辑节点直接接 MathLive，避免强行忽略依赖冲突。

MathLive 的字体通过 Vite 从依赖包打包为本地资源，禁用动态字体路径和声音下载，输入不调用外部 AI 或公式云服务；主文字字体沿用既有界面。检查 20 个同名字体与现有 KaTeX 文件摘要一致，并以原有 PDF/笔记验收覆盖兼容性。

## 数据保护与学习要点

编辑视图是“文字 + 公式节点”，保存仍是现有的普通文字和 `$...$` / `$$...$$`，不更换数据库结构。未编辑的公式保留原始字符串、空白和分隔符，未知命令不因加载输入区而改写。只有实际编辑该公式时才从 MathLive 获取新的 LaTeX；空占位符是编辑辅助，不将其专有命令写入保存内容。

复制整段会序列化成通用文本与公式；粘贴先按纯文字或标准 LaTeX 剪贴板类型读取，不把外部 HTML 当作应用结构导入。外部清空、提交后重置与用户继续输入有不同处理，避免每次父组件更新都重建公式、打断光标。文本撤销/重做复用 ProseMirror，公式内部复用 MathLive。

理解这次修复的关键：普通文本框只存字符，无法在字符流里嵌入一个真正能编辑分子、分母的控件。需要把编辑视图组织成文字节点与公式节点，再在保存时还原为原有格式。这样既能改善输入体验，也能继续使用已有课堂转写、笔记整理与 PDF 导出链路。

## 公式边界删除修复

此前正文将公式当作原子节点，光标紧邻公式时按退格会删掉整个节点。真实 Electron 键盘验收先复现了该问题，再增加优先于默认删除逻辑的边界处理：

- 公式后方按 Backspace（含 Shift+Backspace）进入尾部并执行公式内部退格；公式前方按 Delete 从头部向前删除。
- 单独选中一个公式节点后，Backspace / Delete 均进入尾部删除；主动选中一段正文和公式后，仍可整体删除该选区。
- 分式、上下标复用 MathLive 的结构化删除：先进入末尾结构，再删其中的符号，最后清理空结构。删除最后一个符号时立即移除空公式并把光标交回正文，继续退格即可删除前文；向前 Delete 对称地继续删除后文。也处理已存在的空公式框，避免光标被困住。

实现采用 [Tiptap 自定义键盘快捷键](https://tiptap.dev/docs/editor/core-concepts/keyboard-shortcuts)和 [MathLive 删除命令](https://cortexjs.io/mathfield/guides/commands/)，没有截断 LaTeX 字符串。正文选区定位完成后先建立原生焦点，再交给公式光标和删除命令，保证连续按键落在公式内部；公式修改事件异步写回正文节点，验收等到两者一致后再操作下一步。这样区分了“正文中的一个节点”和“公式内部的数学结构”，避免误用正文的整节点删除规则。

本次补充的真实键盘回归覆盖两侧删除、连续退格、撤销、单节点选择、分式、手打公式上标、空公式与整段删除，并保留复制、保存、重启和回车原有验收。边界处理不改变数据库或原有公式保存格式。

## GeoGebra 风格数学键盘

本机 GeoGebra 窗口处于最小化状态，当前工具未能读取；实际参考来源为已查看的 [GeoGebra 官方计算器](https://www.geogebra.org/calculator) 中的常用、函数、字母和符号键盘。采用浅灰紫底、白色符号键、灰色控制键、紫色选中分页与左右分区，分式、根式、乘方等按键直接渲染为带方框的公式图形。

界面提供 `123`、`f(x)`、`ABC`、`αβγ`、`#&¬`、更多六个分页；字母可切换大小写，原有运算、模板、关系、逻辑、希腊字母与力学符号均保留在“更多”。加入数字、退格、左右移动、下一占位格和回到正文键；回正文键在公式内退出公式，不触发对话发送，正文多行输入中可换行。保持上下自动选位与限高滚动，适配本应用最小的 1024px 窗口和底部单行快捷栏。

先核对 [GeoGebra 开源仓库](https://github.com/geogebra/geogebra)、[MathLive 虚拟键盘](https://cortexjs.io/mathfield/guides/virtual-keyboard/)与现有实现。MathLive 的内置键盘面向当前 math-field，本应用还需在正文、公式和多个输入框之间保留选区，因此修改已有 React 面板呈现与事件路由；直接复用 MathLive 的插入、模板、光标、删除命令和 KaTeX 的按键排版，没有移植 GeoGebra 计算器或自行实现数学布局。公式外的屏幕退格使用浏览器的 `Intl.Segmenter` 按完整字素删除，避免拆坏 emoji；箭头移动复用 Chromium 的选区移动。

验收新增：屏幕键盘填写分子/分母、数字与字母、大小写、三角函数、左右移动、回正文、屏幕退格连续跨公式和 emoji、最后符号移除后的正文退格、向前 Delete 及撤销恢复；保留原有复制、保存、重启验收，另检查常用和函数分页的实际截图。按键标记只渲染仓库内的静态公式，输入内容不发送到 GeoGebra 或其他外部服务。

## 验证和边界

新增往返、未知命令、空行、代码/转义保护、占位符清理测试；真实 Electron 验收覆盖分式占位编辑、正文与两个公式混排、输入区没有原来的代码文本框、复制、撤销/重做、选择替换、手打闭合公式、中文组合输入、公式内回车、单行快捷栏、保存及重启、1024px 布局；课堂旧回归通过共享输入组件的新粘贴入口继续执行。

超过 4000 字符的单个公式保留为文字，避免一次构建过大的可视化控件，不截断原文。

本批改动仅覆盖既有 MathInput 接入的四处输入，其他项目/笔记的独立编辑器不自动改造。未闭合公式暂为文字；不同数学引擎对极少数命令可能有差异，保存源字符串不变，特殊命令仍需按实际使用样例核对。

验收结果：`npm run typecheck`、`npm run build` 与完整 `npm test` 通过，156 项检查零失败、零跳过；原有教材、课堂、PDF、文档包、项目与日历的真实 Electron 回归通过。新增公式输入和重启验收期间拦截外部 HTTP/HTTPS，请求次数为零；多行正文与公式混排的复制、保存和重启往返另做复核。
