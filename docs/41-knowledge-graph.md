# 知识图谱与学习应用回链

工作报告：codex · 2026-11-13

## 本批目标与复用依据

补齐 R3/M2 的图谱与 R4/M3 的应用回链：手动建立知识关系、按学科和名称检索、查看跨学科关系、追踪一个知识点对应的习题与项目任务。保留概念身份、别名、证据与原始教材，不把图上连线视为自动推导或内容认证。

按「直接使用 → 迁移 → 修改 → 自己写」检索：直接使用 [React Flow](https://github.com/xyflow/xyflow) 的交互画布和 [Dagre](https://github.com/dagrejs/dagre) 的布局，二者采用 MIT 许可。核对 [官方布局对比](https://reactflow.dev/learn/layouting/layouting)、[Dagre 示例](https://reactflow.dev/examples/layout/dagre)及[社区非树图讨论](https://github.com/xyflow/xyflow/discussions/2788)。D3 hierarchy 面向树，而知识可多父与交叉；ELK 能处理更复杂的分组约束，但本批无嵌套子图需求，因此先选择 Dagre，并保留手动布局。不复制付费示例或引入外部 Skill。

## 数据与验收约束

- 迁移只追加 23，保留原 knowledge_edges 的端点、关系和未知旧值，追加说明与修订标识；知识节点沿用 knowledge_points。画布位置独立保存，不改知识正文。
- 关系包括前置知识（起点是终点的前置）、推广为、相关；前置环路在主进程事务内拒绝。相关无方向，不能借反向重复建立覆盖说明。
- 编辑/删除检查所选关系修订，删除重建也不能让旧窗口覆盖新关系；拖拽与自动排布只修改布局。
- 复习知识点和任务用途是显式引用；反向列出实际使用，区别于教材/笔记里的名称提及和固定来源证据。删除习题进入回收站后不列为当前练习，恢复后可重新找到。
- 验证升级回滚/旧关系保留、跨学科、循环/陈旧操作、布局事务、任务/习题回链、真实画布和应用重启，完成后运行类型检查、构建与完整回归。

## 使用与设计说明

1. 在「知识与概念」登记名称、别名和释义，打开知识图谱；也可从已有知识点进入图谱并保留选择。
2. 选择起点、关系、终点与说明后保存。拖动节点右侧圆点到另一节点左侧也只生成草稿，确认后保存。前置箭头表示先学起点，再学终点；推广关系需写清适用条件；相关关系不推断学习顺序。
3. 按名称、别名、释义、学科或关系筛选，紫色虚线突出跨学科联系。「仅看所选点与全部邻接知识」会跨越学科筛选，避免隐去桥接知识。
4. 拖动节点或使用方向键调整位置；自动排布只整理当前显示范围，位置会保留到重启后。图谱缩略图、平移、缩放和适应画布由 React Flow 提供。
5. 在习题中选择需复习知识点，在项目任务中填写知识用途后，知识列表及图谱详情会列出这些应用；点击可进入题目或定位任务。无项目的任务会打开对应日程编辑入口。

知识实体可有多个前置和跨学科关联，所以图谱采用有向图而非单父树。主进程在事务内检查前置环路与修订标识，防止绕过界面或旧窗口覆盖新关系；布局是独立的展示数据。名称提及、证据摘录、练习复习点和任务用途保持不同语义，后两者才计入本批应用回链。

## 当前边界

- 关系由用户建立和确认；不自动推断、合并知识实体，也不将连线当成数学定理的充分证明。未知旧关系保留原值，编辑时需明确转换到支持的类型。
- 当前新关系总量上限 5000，单次布局保存最多 2000 个知识点；没有验证万级节点性能。应用回链每组 50 条，可翻页。
- 布局采用最后一次保存结果；关系内容有修订保护，布局尚未提供多窗口冲突合并。
- 任务回链沿用已有任务与知识用途，版本化项目文档、自动排程、FSRS 和预回答缓存仍为后续事项。图谱依赖不涉及远程服务，当前批次不增加 AI 请求。
