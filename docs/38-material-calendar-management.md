# 教材管理与日历日程

## 2026-11-13 时间轴起点（codex）

日/周视图默认勾选“从 [06:00] 开始”，时间可输入，开关和时间选择保存在本机；取消后从 0:00 开始。当前视图内存在更早的安排或截止时刻时，向前展开到其所在的半小时；跨午夜且在下一天仍有持续时间的日程展开到午夜。全天日程使用独立行，不改变时间轴，视图之外的早间日程也不影响本视图。删除或改期后重新计算，日/周/月切换继续使用既有日历组件。

工具栏按“左箭头—日期—右箭头—今天”排列；日/周/月在右侧。鼠标松开后不残留焦点阴影，键盘操作仍有可见焦点，当前日/周/月的选择状态保留。原生鼠标按下/抬起验收和按钮坐标顺序检查通过。

日期标题固定 270px 并居中，日/周/月切换验收确认右箭头与“今天”的横坐标不变，避免日期长短变化带动按钮移动。

点击日期可填写 `YYYY-MM-DD` 并跳转；按实际年月日校验，非法输入显示“请输入正确日期”且不移动日历。周视图提供起始/结束两个输入：只改结束日就定位其所在周；起始日改变（包含两项同时改变）则定位起始日所在周。该表单用于定位，不用于建立日期范围，所以无需两项恰好落在同一周。单元测试涵盖闰年与非法日期，Electron 验收覆盖非法拒绝、周内定位、结束日单改和两项同时修改，跳转后按钮横坐标保持不变。

编辑面板以右上角叉号关闭，比较打开时的初始表单和当前值，只有未保存的实际改动才确认放弃；空白表单、自动填入的日期和未修改的已有日程直接关闭。新建、切换日程、点击日历空白处也沿用此判断。设置的个性化卡片移除 720px 限宽。新增 Electron 验收覆盖空表单关闭、拒绝丢弃后的保留、未修改旧日程关闭、7:15 自定义时间轴和 1024px 个性化全宽。

复用 FullCalendar v6 的 [slotMinTime](https://legacy.fullcalendar.io/v6/slotMinTime)、scrollTime 和 datesSet 配置，无新依赖或数据库修改。单元测试覆盖日期范围、截止时刻、全天、跨日与半开区间；真实 Electron 验收覆盖默认值、勾选切换、页面返回保留选择、5:15 日程展开至 5:00、删除后回到 6:00，以及原有教材管理和 ICS 回归。类型检查与构建通过。

## 本批交付与使用

材料库选中教材后展开“管理教材”，可修改名称、所属学科和教材类别。删除会移入回收站；在对应学科的回收站选择教材可恢复。原始文件、提取版本、语义条目和课堂来源不删除。移动教材后，它从原学科书架移至新学科；当前阅读和历史引用仍使用原有 ID。

日程页提供日、周、月视图；日/周使用真实时间轴，支持点击空白处新建、点击日程编辑和删除，项目任务仍是同一条任务。可填写开始、结束、全天、截止、地点、说明和状态。地点显示在名称下方，长名称、地点也可通过悬停查看。右上方白色“导入课表”按钮位于“新建日程”下方，入口名称不绑定文件格式；当前文件选择支持 ICS。导出全部日程生成 ICS，无安排和截止的任务明确提示未包含。

使用八组清新浅色背景配深色文字，分类优先使用关联项目的学科，其次关联项目；独立课程按名称匹配已有学科，没有匹配时按考试、实验、讨论会议或归一化课程名称分组。相同分类稳定同色，课程的“第几讲/预习/复习/作业”等常见后缀不影响分组。有限色板可能使不同分类同色；名称和时间仍是识别依据。截止标记加虚线，已完成项降低透明度；本批没有自动调用 AI 分类。

## 导入确认与时间冲突

1. 选择学期日期范围（结束日期包含当天），读取文件并预览，不立即写入数据库。
2. 展开周期课程，展示日期、时间、地点、重复项和解析提示。
3. 检查新增课表与已有未完成安排、同批新增课程的时间重合，列出冲突双方和各自时段。
4. 有冲突时默认不能确认；勾选“忽略冲突，仍导入全部新日程”后可继续。忽略会保留双方，不会自动删除或移动任何一方。
5. 提交前再次检查冲突。如果预览后日程有变动使确认指纹失效，返回新的冲突报告并清除旧勾选，要求重新核对。

区间使用 `[开始, 结束)`：09:00–10:00 与 10:00–11:00 不冲突。仅截止时刻不视为占用时段；已完成项和重复导入项不参与冲突判断。缺少结束时间的普通日程按一小时显示和检查，全天按本地日历的下一天零点结束。超过 200 对冲突只列出前 200 对并提示还有更多，避免预览无限增长。

## 复用方案与选择依据

依照“直接使用 → 迁移 → 修改 → 自己写”，先检索 GitHub 与社区中的 React 日历方案，再检查上游接口、许可、React 19 兼容声明及本地运行。选择如下：

| 能力 | 直接复用 | 依据和边界 |
|---|---|---|
| 日/周/月和时间轴 | FullCalendar 6.1.21，core/react/daygrid/timegrid/interaction，MIT | [v6 React 文档](https://legacy.fullcalendar.io/v6/react)与[上游 React 适配器](https://github.com/fullcalendar/fullcalendar-react)；标准插件满足本批，不使用付费资源视图 |
| ICS 解析、周期规则、例外与序列化 | [ical.js 2.2.1](https://github.com/kewisch/ical.js)，MPL-2.0 | 直接使用未修改的包，避免自行编写 RFC 5545 语法和周期展开器 |
| 缺失内嵌时区定义时的 IANA 时区换算 | [Temporal polyfill 0.5.1](https://github.com/js-temporal/temporal-polyfill)，ISC | 使用系统 Intl 时区数据，拒绝未知或无法明确的时间；内嵌 VTIMEZONE 仍由 ical.js 解释 |
| 教材管理、冲突及确认流程 | 本地薄层适配 | 复用现有稳定材料 ID、统一任务和事务；区间比较、受控 IPC 和分类配色是本项目业务规则 |

日历相关版本固定在同一套 v6 API，避免混用插件版本。安装时发现旧锁文件遗漏已在清单声明的 onnxruntime-node；补齐并固定为 1.23.2，避免新日历依赖安装顺带升级 OCR 原生运行时。模型和个人教材未进入版本库。

## 数据、响应与故障恢复

追加 migration 021，为统一 tasks 增加结束时间、全天和地点，新增导入凭据表。不修改此前已发布迁移，不另建一份与项目任务脱节的日历数据。

凭据按事件 UID 与实例标识去重；删除日程后保留空关联的凭据，防止重复导入把已删除课程重新生成。重复导入也不覆盖人工修改。导出携带本应用的任务/凭据标识，回到原数据目录导入时识别重复。每次课程是独立日程，修改或删除只影响一次；不做与原始 ICS 的持续同步，也不支持“整系列改期”。

ICS 解析在线程中运行，不占课堂转写的主进程；限制 5 MiB 文件、366 天日期范围、5000 个事件/展开实例、展开步数和解析时间。预览只在主进程保存，绑定窗口和当前数据库，15 分钟失效；取消、窗口关闭及应用退出会释放预览/解析任务。冲突检查使用排序区间扫描并限制候选已有日程数量。

整批导入使用单个 SQLite 事务；中途失败不留下半份任务或凭据，同一有效预览可重试。导出经既有路径保护，禁止覆盖应用数据目录内文件，先写同目录临时文件再替换目标。原 ICS 始终只读，不获取其中的远程链接、附件。

## 验证与学习要点

`npm run typecheck`、`npm run build` 与完整 `npm test` 通过：152 项检查零失败、零跳过，另包含真实 Electron 的教材、课堂、笔记包、项目和日历验收。新增自动验收覆盖：v20 升级及迁移事务回滚；重命名/移动/删除恢复后的稳定 ID、原件摘要与课堂引用；真实 Electron 日/周/月、编辑删除与 1024px 布局；ICS 周重复、EXDATE/RDATE、改期/取消例外、自定义及 IANA 时区、夏令时、全天跨日、导出再解析；预览取消、重复导入、人工编辑及删除保护、整批失败回滚与重启恢复。

冲突验收覆盖已有与同批、相邻不冲突、包含与跨日、未勾选禁止确认、明确忽略后导入、预览后新增安排使旧确认失效；配色验收检查八种背景与文字的对比度至少 4.5:1。真实工程热力学教材的 PP-OCR 依赖回归及重启恢复另外通过，第 26–27 页置信度约 97.35% / 84.88%；原件不变。首次在依赖自动解析至 1.31.1 时识别完成但测试进程退出超时，另一次退出跟踪正常，原因未确定；不将其视为日历逻辑失败或已修复的 OCR 故障，交付锁定 1.23.2 并通过完整 OCR/重启验收。不把合成课表验收当作学校真实 ICS 的兼容性证明。

理解这次实现的关键，是把“身份”和“显示位置”分开：教材改名和移动不改变身份，所以课堂引用不会断；项目任务改期也不复制身份，所以两处编辑一致。时间冲突则是对区间的比较，不能只比开始时间，也不能把相邻边界算成重合。预览加确认仍需在写入前复核，因为用户看到预览后，数据还可能发生变化。

后续保持原规划：其他课表格式、可人工调整分类/颜色、自动排程、系统常驻提醒、任务依赖与复习排程另分批构建。本批只提供启动时到期通知，应用关闭时的可靠提醒未交付。回收站不物理清理文件，磁盘空间回收另行设计。


## 补充：新建和编辑的冲突检查

“新建日程”和日历空白处新建均在保存时检查与已有未完成安排的重合；编辑、改期也使用同一路径，并排除日程自身。发现冲突保留表单但不写入，用户可改时间或勾选“忽略冲突，仍保存日程”。修改表单会清除旧的冲突报告和勾选；保存时复核最新数据库，旧确认不能绕过后来新增或修改的冲突。相邻区间、全天和无结束时间的规则与课表导入一致。

主进程把校验、区间检查和保存置于一个事务内，冲突未确认时回滚整个操作，避免生成空任务或覆盖原来的改期信息。项目任务沿用其原 ID 和知识引用；不另建副本。新建/改期界面、拒绝后不落盘、忽略后保存、修改时间清除旧确认及相邻不误报均加入验收。
