# 本地 OCR 与教材校正

> 2026-11-11 · 设计、实现与报告：codex · 含实施前方案与交付证据

## 首批目标与复用决策

扫描页先得到有页码、可核对的文字，再进入后续语义条目整理。采用已在依赖树中的 PDF.js、@napi-rs/canvas 与 Tesseract.js，不另装 Python 或系统 OCR。依赖显式登记，不能靠其他库恰好带入。OCR 不等于公式/图表理解，不把识别分数当成正确率。

调研依据：[Tesseract.js FAQ](https://github.com/naptha/tesseract.js/blob/master/docs/faq.md)说明 PDF 需先绘制为图像；[API](https://github.com/naptha/tesseract.js/blob/master/docs/api.md)支持本地语言包、文字/区域输出与复用 worker；[本地安装](https://github.com/naptha/tesseract.js/blob/master/docs/local-installation.md)支持本地路径。比较 [RapidOCR](https://github.com/RapidAI/RapidOCR) 和 [Docling OCR](https://github.com/docling-project/docling/blob/main/docs/concepts/OCR.md)，后者保留为复杂中文版面、公式/图表的后续候选；当前先直接复用已安装引擎，实测不足再迁移，不自写识别算法。

## 生命周期与数据约定

- 每次指定 PDF 物理页码范围，最多 20 页，后台识别；明确进度、取消、失败重试及重启恢复。长书不在一个不可恢复任务里强行全部识别。
- OCR 产生新派生版本，共享不可变托管原件；原始版本、块 ID、历史课堂引用不改写。未选页继承所选父版本的文字，已识别页不会在下一批丢失。
- 保存每页原始 OCR 文字、识别分数、像素尺寸与行框，以及语言包/引擎标识。前台可对照原页校正；校正也产生新版本，保留 OCR 原文和上一版。
- 字符、条目数、页数、图像像素、语言包体积和任务时间均有限制；主进程协调数据库，后台 worker 做绘制和识别。与原有导入队列共用工作锁，迁移数据前须结束任务。
- 中文/英文语言包采用官方 tessdata_fast 的固定提交，下载核对 SHA-256；用户明确点击准备语言包后才下载，识别时只读本地数据。教材不上传到识别服务。
- 只有完成且校验通过、且当前版本仍为其父版本的任务才更新当前版本；期间若用户已导入更新版本，完成结果保留为可选择的分支。失败/取消保留任务可重试，不影响之前可阅读的版本。

## 实施前界面计划

沿用材料库的安静阅读布局：背景 #f7f7f5、正文 #1f2328、辅助 #6b7280、边线 #e5e5e0、操作 #4f46e5。按钮和导航沿用系统中文字体；校正正文用宋体及系统回退。阅读器顶部折叠的“扫描页识别与校正”区域包含语言包就绪状态、页码范围、识别操作与任务反馈。

校正界面按页对照：PDF 原页预览、OCR 原文、校正输入；保存按钮明确为“保存为校正版”。不把扫描图中的识别错误静默改成教材原文。显示类型为“原始提取 / OCR / 校正版”，让用户能辨认同一原件的派生版本。暂不把固定长度 OCR 检索块当作定义/定理等语义条目。

## 验收计划

验证合成扫描页的实际识别、中文真实教材正文样页、按页搜索与概念回链；保留旧块/课堂引用；第二批继承第一批；人工校正保留 OCR 原文；失败、取消、重启及语言包缺失/损坏不产生半完成版本。检查原件散列和不联网识别条件。使用隔离数据目录和本地临时材料，用户教材与模型不进入 Git。

## 使用方式

1. 在材料库导入 PDF，等待原始文字提取结束，打开“扫描页识别与校正”。
2. 首次点击“下载中英文语言包”，约 6.3 MiB；仅这一步联网，下载来自官方固定提交并验证摘要。识别线程禁止联网。
3. 输入 PDF 实际页序号的连续范围，每次 1–20 页，点击“识别为新版本”。进度、取消和失败重试沿用材料任务区。不会自动识别整本长书。
4. 切到完成的新版本，在“核对第 … 页”对照原件、OCR 原文和校正输入，点击“保存为校正版”。只有已识别页可校正；旧识别原文仍可查看。折叠面板保留当前草稿。
5. 新版文字可在材料中搜索，并参与已确认概念别名的自动关联和回链。历史课堂段落继续指向旧版块。

语言包是所选数据目录下的缓存，当前数据迁移只搬数据库和教材；换到新数据目录后需重新准备语言包。归档材料不能开始新识别/校正。OCR 结果仍是带页码的检索块，不是已经识别出的定义、证明、配图等语义条目。

## 实现与故障定位

追加迁移 v8，旧版本默认为 `original`；派生版本记录父版本、处理参数和来源类型，按页保留 OCR 原文、校正文、分数、行框及引擎/语言包标识。识别完成与派生块写入在同一事务内，失败不会留下半套可阅读文字。共享原件仍通过托管路径校验，不复制整本书到每个派生版本。

复用 PDF.js 绘制和 Tesseract.js 识别，单页最多约 600 万像素、单边不超过 8192，任务最长十分钟。没有自行实现解码或识别算法。语言包采用官方 `tessdata_fast` 提交 `87416418657359cb625c412a48b6e1d6d41c29bd`，运行时再次检查 SHA-256；原始文字保持不变，仅显示/检索文字清理汉字间的水平空格。

真实 Electron 验收定位到 `wasm-feature-detect@1.10.0` 的 `import.source()` 语法导致线程初始化失败；在 Tesseract 依赖范围内固定到已验证的 1.8.0。保留作用域明确的依赖覆盖和锁文件，避免修改第三方源码或吞掉错误后宣称 OCR 成功。

## 交付验证与质量边界

- `npm test`：数据库/整理/切块检查、25 项逻辑测试，以及真实 Electron 的材料、概念、课堂和重启集成检查通过。
- `npm run typecheck`、`npm run build` 通过。v7 → v8 升级保留旧块及课堂引用；分批继承、人工校正、旧分支不覆盖当前版、不完整结果回滚、缺失/损坏模型及下载摘要不符等已检查。
- 可选真实识别验收 `npm run test:ocr -- <本地配置.json>`：三页纯图像合成 PDF，覆盖中英文、空白页、实际界面发起与保存、折叠保留草稿、取消/重试、禁联网识别、1024 宽界面、应用关闭后重新启动并恢复中断识别。
- 同一验收开启 `downloadModels: true`，在空语言包目录中通过应用的真实下载接口准备语言包，再禁联网识别及重启，全部通过。
- 用户提供的热力学教材：原件 353 页、无文字层；第 26–27 个 PDF 页面识别约 5.4 秒，引擎分数均 90，“热力学”检索及概念回链通过，原件 SHA-256 不变。分数不是正确率，没有逐字标注的准确率评估。
- 第 17–18 个 PDF 页面为目录，多列及点线导致漏字、英文误识别，分数 62/63；本轮未将其认定为合格。正文仍有错字、断行，需人工核对。公式结构、表格、图片及阅读顺序不在普通 OCR 的保证范围，后续用相同样页比较 RapidOCR/Docling 等候选再决定迁移。

测试教材、识别输出、截图、数据库与语言包只留在隔离临时/忽略目录；不入库。标准测试不下载模型。可选配置字段为 `modelDirectory`、可选 `downloadModels: true` 和 `real: { file, from, to, query? }`，不能通过应用接口注入语言包路径/下载地址。Windows 安装包与复杂教材整本质量尚未验收。

依赖复查仍为原有的 6 个 moderate，集中在 electron-builder/minimatch 打包链，无 high/critical；本轮 OCR 依赖未新增审计告警。未采用审计工具建议的跨主版本降级，打包链调整留到安装包验收时连同构建验证处理。

学习要点：识别器解决“图像中写了什么”，版本与引用解决“这段文字来自哪一版、哪一页”。把两者分开，后续可以替换识别器，并在确认文字上继续构建语义条目，而不改写已有课堂证据。
