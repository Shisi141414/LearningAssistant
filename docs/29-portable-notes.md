## 当前交付与完整目标

本批完成笔记 `.ladoc` 的公开契约、严格校验、工作线程编码/读回及实际界面导出。下一批接通预览、独立编号导入、来源保留、重复保护和独立目录验收；**当前尚不能通过界面导入笔记包，不把生成 ZIP 当作交换闭环已完成**。教材包 0.2 的现有导入/导出继续兼容。

完整目标是让笔记在独立数据目录恢复原始口述、整理稿、语义类型、章节、证明/解答归属、公式、标注、相关概念和知识证据，并能继续人工编辑。导出所选固定修订，不是整个应用数据库备份，不打包录音、供应商配置、其他笔记或教材原件。

## 开源调研与选择

先检查了 [yauzl](https://github.com/thejoshwolfe/yauzl)、其 [社区读取错误讨论](https://github.com/thejoshwolfe/yauzl/issues/174)、[BagIt 包装规范](https://www.rfc-editor.org/info/rfc8493/) 与 [笔记关联导出社区案例](https://www.reddit.com/r/ObsidianMD/comments/1mn4j71)。可移植文件需要同时考虑内容快照、完整性和关系；单纯导出 Markdown 不足以表达结构与原始来源，完整引入另一套归档规范也不能直接替代应用的语义验证。

选择直接复用已安装的 yazl/yauzl、Ajv、既有教材包编解码与外部保存流程。提取可参数化的文档契约，笔记和教材共用路径白名单、实际字节上限、CRC/SHA、UTF-8 解码、工作线程、临时文件清理及原子替换。相关概念选择也共用原匹配器，额外扫描所选修订的原始口述。未复制第三方代码，未新增依赖，不声称符合完整 BagIt 标准。

## 格式与来源

- 标准 ZIP，根条目 `document.json`。笔记类型为 `format: learning-assistant/note`、`schema_version: 0.1`；教材仍为 `learning-assistant/document`、`0.2`。
- 类型见 [note-package.ts](../shared/note-package.ts)，结构约束见 [note-package.schema.json](../shared/note-package.schema.json)，共用教材 Schema 的条目/公式/概念定义；Ajv 注册教材 Schema 为 `material` 后编译笔记 Schema。程序再检查覆盖、编号、引用、来源位置、原文散列和总量，拒绝坏数据而非静默修补。
- `document` 指定原笔记、文档、所选修订和学科名称；`sources/state/origins` 保存整理稿及结构、原始口述、段落版本、整理模型、记录时间与教材位置快照。模型只保存出处名称，不保存密钥。
- `annotations/evidence` 是导出时能找到且属于所选段落的标注/证据，保留记录时间。它们不冒充历史修订当时的状态：标注记录当前段落版本，证据保留摘录和 SHA；`matches_revision` 表明是否与所选来源对应，不对应的仍携带但明确标记。
- `concepts` 仅携带正文、原始口述提及或证据引用的相关确认概念及别名；不携带整个知识库。
- `assets` 当前必须为空：笔记配图尚未接入，不把教材位置当作已经打包的教材文件。没有录音时间轴时，记录时间也不能冒充录音偏移。

上限沿用容器的 192 MiB 归档、16 MiB 清单与严格解压预算；笔记最多 5000 个来源，原始口述与整理稿各最多 200 万 UTF-16 字符，结构最多 5000 条。超限显式拒绝并建议拆分。笔记包不允许额外文件；教材容器的原件/图片检查保持不变。

## 导出行为与验证

笔记统一阅读页显示“导出笔记文档包”；课堂在“阅读与导出选项”内显示。保存全部条目，当前搜索或类型筛选不会删减内容。读取固定修订，不自动把最新转写同步进旧快照；历史修订也可导出。导出期间暂停课堂文档刷新，原始转写仍保存。

系统保存框选择数据目录以外的位置；只有工作线程完整生成并校验后才替换目标。取消、并发请求、超时、坏包和关闭窗口都不得覆盖已有目标；教材和笔记导出共用同一任务锁。无需新增数据库迁移。

新增 5 组逻辑检查，覆盖固定快照、公式/标注/证据及匹配状态、未知字段/伪造来源/路径/坏引用、相关概念筛选、ZIP 读回/CRC/穿越/多余附件、已有目标与取消、非法 IPC。教材包现有编解码检查保留。

复核补充：当前段落删除后，证据的段落外键会置空，但出处快照仍保留。导出改按证据内的原笔记/段落身份查找，验证旧修订的证据和原始来源仍完整携带；标注只携带数据库中仍存在的导出时记录，不伪造已删除的历史标注。旧 PPT 的转换后幻灯片锚点亦通过契约与 ZIP 往返验证。

`scripts/test-note-package.cjs` 使用真实隐藏 Electron 窗口、预加载接口、主进程、SQLite、工作线程和独立暂存目录：实际点击取消、受管位置拒绝、筛选后历史修订保存、原始口述/结构/公式/标注/证据读回、无关概念和私密配置排除、并发/取消保留旧目标、临时目录清理；真实重启后再次解码并导出同一历史修订。暂停线程仅用于稳定制造取消时机，正常生成与读回使用真实 ZIP 线程。单独运行 `npm run test:note-package`，完整回归加入 `npm test`。

完整回归、125 项逻辑检查、类型检查、构建、文档链接及差异检查通过，既有教材包、课堂、AI 审核、笔记和 PDF 验收继续通过。1024 × 768 实际导出状态截图已查看，筛选为空时仍正确导出全修订并提示不匹配的标注。

## 下一批导入要求与验收

1. 通过系统文件选择框检查笔记包，只返回摘要与一次性票据；预览取消不得写笔记。选择目标学科及是否携带相关概念/证据，明确当前标注与所选修订的匹配情况。
2. 原子生成新笔记、段落、来源快照、语义修订及稳定编号映射，保留原始记录/模型信息，不使用来源文件内的数据库编号覆盖本机记录。失败整体回滚；重复导入定位已有结果，保护导入后人工修改。
3. 外部教材锚点只作为来源快照保留。没有验证并关联本机教材前，不把外部编号路由到本机可能同名的记录；界面显示未关联的外部来源。重启与后续段落同步也不能丢掉出处。
4. 匹配修订的标注/证据可重连；不匹配的作为明确的历史出处保留，不错误标到新的正文位置。概念名称/别名冲突按现有人工保护规则处理，保留决定与编号映射。
5. 独立空数据目录中导入本批包，核对每个来源字符、结构、公式、原始口述、标注和证据；再编辑并重复导入、重启、取消、制造失败，验证数据不丢失。教材包与笔记包交叉选择时给出明确类型提示。

这些要求未通过前，笔记可移植交换仍为未完成项。后续项目、日程和备忘按总路线图保留，不因本批格式导出提前标记完成。
