## 先检索，再接入

依照“直接使用 → 迁移 → 修改 → 自己写”比较以下方案：

| 方案 | 已有能力与接入判断 | 本轮选择 |
| --- | --- | --- |
| [OfficeParser](https://github.com/harshankur/officeParser) | Node.js，Office 结构树、分块、表格与来源元数据；可直接放入 Electron 的解析工作线程 | 直接使用 DOCX/PPTX 解码、结构分块，不自写 OOXML 解析器 |
| [PDF.js](https://mozilla.github.io/pdf.js/) | PDF 页面读取与文字提取；页码与页尺寸由原文件产生 | 直接使用 PDF 页级提取；保留扫描页位置并提示 OCR |
| [Docling](https://github.com/docling-project/docling) | Python、多格式、布局/表格与 OCR 管线；值得用于后续复杂教材 | 当前接入需增加 Python 运行时、模型分发与进程协议，留作复杂扫描件候选 |
| [MarkItDown](https://github.com/microsoft/markitdown) | Python、多格式转 Markdown | 当前需求还要原件位置与结构条目；本轮先选择可直接接入现有 Node 架构的库 |

同时查阅 [OfficeParser 社区问题区](https://github.com/harshankur/officeParser/issues)，以实际格式样例验证兼容性，不将 README 的支持清单等同于本产品已验收的效果。上述接入成本判断是针对本仓库的工程推断，不是解析质量排名。

本轮关闭远程资源访问、OCR 与附件提取，不自动下载模型。OfficeParser 8.7.1 对 Node 有安全版本要求；应用内 Electron 45.2.3 的 Node 24.22.2 满足条件。本机开发命令行 Node 24.21.0 低于其声明范围，需要更新开发环境后再宣称所有开发环境兼容。

## 界面实施前的设计

沿用现有浅色、安静、内容优先的风格。左侧书架按当前学科列出材料，右侧显示选定版本、导入状态与可搜索条目；学科未选择时，导入区明确要求选择。阅读文字以正文为主，来源位置与处理警告为辅，不用装饰性图表。

PDF 按页、PPT 按幻灯片、Word 按逻辑结构条目显示定位。条目链接携带材料和版本，不随新版本变更。原件通过系统应用打开；本轮不将纯文本视图称作原版排版预览。下一轮再把阅读器放入课堂左侧。

## 数据边界

- 原件复制至用户数据目录的 `materials/<版本ID>/source.<格式>`，保存 SHA-256 指纹，原路径不交给渲染进程。
- 一个材料有多个版本，每版有独立条目 ID；成功版本不原地重解析，导入新版本不会删除旧条目。
- 解析在独立工作线程顺序进行，状态入库，支持失败重试、取消与重启恢复。单件上限 50 MiB，解析有时间与堆内存限制。
- 数据目录迁移包含材料，解析或复制期间占用工作锁，避免搬迁途中写入。
- 旧 DOC/PPT、OCR、公式识别与精确段落框不在本轮完成范围；保留原件并明确提示能力边界。

## 验证与后续

- `npm test` 通过：原数据库/整理/切块冒烟、10 个可靠性回归，以及真实 Electron 主进程—preload—renderer—解析线程的材料检查。
- 材料样例覆盖 DOCX 中文与表格、PPT 演示顺序不同于文件名顺序、PDF 文字页与空白待 OCR 页。验证重复导入去重、文件内容指纹、旧版条目不变、查询、取消与重试、失败状态、归档保留链接、原件访问和界面条目锚点。
- 再次实际关闭并启动隔离应用，验证中断解析自动恢复。所有检查使用临时目录与生成样例，不读取用户资料或密钥。
- `npm run typecheck`、生产构建通过；检查了材料界面的实际截图。
- `npm audit` 当前报告 6 个 moderate，集中在 electron-builder/minimatch 开发打包依赖链，无 high/critical；未强制改动整个打包工具链。Windows 安装包尚未验收。

这些检查不能代表复杂教材公式、扫描 OCR 或真实长篇教材质量已验收。R2 的课前起点、人工校准、转写来源锚点现已基于稳定版本和条目交付，见 [R2 记录](08-classroom-material-link.md)。用户随后明确下一步要将材料统一为可分类、关联、排版与检索的“学习文档”，转换/OCR 作为导入适配层，而非最终存储形式。

后续补充（codex，2026-11-11）：扫描 PDF 的指定页 OCR 与人工校正首批已实现，能力及实测边界见 [OCR 记录](11-local-ocr.md)；本页前述“未启用 OCR”描述保留为原始文字提取阶段的历史范围。普通导入仍先提取文字，不自动识别整本扫描书。

后续旧 DOC/PPT 已通过本地 LibreOffice 接入导入队列，原件和只读转换产物分别保留，见 [转换配置与验收](14-legacy-office-conversion.md)。上述早期“不支持旧格式”属于首批历史范围；无需先手工转换，但须配置本机转换工具。
