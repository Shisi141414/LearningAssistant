# 项目要求、计划书与版本化文档

工作报告：codex · 2026-11-13

## 目标与选型

接续 R4：在项目详情中管理项目要求、计划书、成果与报告、其他项目文档。采用已有内部学习格式，保留版本和导入来源，关联知识点，支持 PDF。与已有目标摘要、里程碑、统一任务配合，不把单一文本框当成完整项目资料管理。

按「直接使用 → 迁移 → 修改 → 自己写」检索了 [Joplin 的历史机制](https://github.com/laurent22/joplin/blob/dev/readme/dev/spec/history.md)、[社区关于历史链完整性的反馈](https://github.com/laurent22/joplin/issues/13782)、[Tiptap 扩展体系](https://tiptap.dev/docs/editor/core-concepts/extensions)和[数学扩展](https://tiptap.dev/docs/editor/extensions/nodes/mathematics)。Joplin 是完整应用，迁移整个应用不符合本项目现有 SQLite/来源/内部格式的边界；Tiptap 的编辑能力已经引入，本批直接复用现有 Tiptap/MathLive 输入、教材条目操作、公式显示和 Electron PDF 导出，不新建一套编辑器或引入云端版本服务。历史采用完整快照，每版可独立读取；没有复制 Joplin 的源码或差分历史实现。

## 使用流程

1. 在项目详情的「要求、计划与文档」新建文档，选择用途，输入正文与公式，关联已有知识点后保存。
2. 保存后以内部条目排版，可整理语义类型、标题、拆分/合并、章节归属、证明/解答关系和公式校正。沿用教材的保护规则，含公式校正的条目拆分前要先移除对应校正；原文保留。
3. 文档元信息编辑默认只改标题、用途及知识关联，保持现有条目、图文和公式校正。「替换整篇正文」会明确确认重建本版结构及移除原有配图，旧版仍保留。正文中的有效数学输入保存为公式节点，阅读与 PDF 都渲染。
4. 从材料库导入：先通过已有 Word/PDF/PPT 管线导入文件、打开学习文档，再在项目中选择材料与用途。复制材料当前的固定修订、来源、条目结构、公式与配图，并保留原件/版本链接。重复导入同一项目、用途和修订会打开已有文档，不覆盖人工修改；新的材料修订可另行导入。
5. 修订选择器可只读查看历史；恢复旧版会生成新版本，恢复前版本仍可查看。文档删除进入回收站，可恢复；归档项目保留文档。原有「删除项目」行为仍明确级联其文档及修订，其他项目不受影响。
6. 文档关联的知识点可直接打开知识页；知识页和图谱详情也能反向找到使用该知识的项目文档。导出 PDF 固定当前所选修订，保留类型、公式、配图和来源对照。

## 数据与协作保护

- 只追加迁移 24：`project_documents` 与 `project_document_revisions`，不改原项目、任务、知识点或已发布迁移。项目外键约束所属关系；材料导入去重键包含用途及固定修订。
- 修改、结构整理、删除/恢复和历史恢复均检查当前修订标识；事务失败不留下半成品。删除与恢复也生成新修订，旧窗口不能借此覆盖变化。
- 修改冲突时保留页面草稿；「读取最新修订」会确认放弃草稿，用户可先复制内容。编辑期间导航或关闭会提示；本批没有自动持久化未保存草稿。
- 每个修订保存完整来源与结构，标题/用途是当前列表索引。复制来源不复制原件和附件文件；已有材料库托管原件与配图。材料进入回收站不破坏文档，硬删除学习来源受原有外键保护。
- 导入上限沿用学习文档 200 万字符；手动替换正文上限 20 万字符。知识关联最多 32 项，条目每组显示 100 条。长文件解析仍由现有后台材料管线完成。
