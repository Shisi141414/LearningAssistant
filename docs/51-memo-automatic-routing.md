# 备忘自动整理、离线补处理与规则控制

2026-11-14 · codex

## 使用方式

备忘页展开“自动整理”，选择模型、允许处理的学科（可另选未分类）以及允许归档的知识/待办种类，勾选启用并保存。默认关闭。只处理启用之后保存的新修订；已有原文需要明确点击“处理已有待整理”，每批最多 100 条。启用边界使用数据库修订序号，不依赖毫秒钟点，避免同一毫秒或系统时钟回拨造成旧资料意外外发或新资料遗漏。

原文先落库，处理时只将这一条固定修订、其记录时间和时区发送给所选模型。清楚的知识、待办及混合条目按规则自动进入已有知识库和统一任务系统。新知识需要学科；同名/别名知识直接复用，不覆盖原释义。无任何时间表达的清楚待办可进入“待安排”；出现日期但不明确时保留在待整理，不能把时间信息悄悄丢掉后当作无日期待办。混合候选包含未授权种类时整条留待确认，不只归档其中一半。

原文页直接显示本条处理结果与原因，可以停止或按当前规则重试；折叠面板显示最近 50 条带原文摘录的处理记录。来源修订、知识和任务回链、归档记录及撤销沿用前批。撤销后的修订保留去重身份，不会被自动创建回来。用户手工改过的任务受原有撤销保护。

## 哪些条目需要确认

- 模型返回不确定项、项目想法/其他记录，知识没有学科，或同名知识存在多个候选。
- 时间含糊、已经过去、起止不完整、地点没有原文依据、与现有课程/学习时间块冲突。
- 已有同名同起止/截止的未完成任务：给出重复提示，由用户决定，不自动合并或覆盖。
- 同一备忘的旧修订已经生成待办：编辑后的候选交人工核对，既不自动修改旧待办，也不因标题或时间改变而再建一份。
- 模型或网络持续失败，或模型/供应商配置在请求后变化。

冲突不会自动忽略。用户可在原有整理草稿中核对并明确忽略冲突后归档。

## 时间核对

模型输出的日期不是自动写入的唯一依据，也不使用其自报置信度作为通行证。复用 Temporal，按原修订保存的 IANA 时区和日期核对原文明确钟点，支持单一 `YYYY-MM-DD` / `YYYY年M月D日`、今天/明天/后天、本周/下周具体星期，搭配 `HH:mm`、数字“点/分”、上午/下午等表达，以及明确连接的同日时间区间。模型日期必须与核对出的时间逐个一致；夏令时歧义直接拒绝。

“周五”未说明哪周、只有日期没有钟点、“下次课前”、重复规则、多日期、跨日区间、半点/刻钟、估计时间和改期指令仍交人工确认，不擅自猜测。该核对器刻意保守：复杂条目中混杂其他数字或多个时间表达也可能进入待整理。它不是完整自然语言时间解析器；后续继续扩展真实中文样例及课程日历解释。

## 持久状态与失败恢复

追加 migration 030：自动整理设置和按原文修订唯一的处理队列；保留规则快照、选定模型、尝试次数、识别记录、原因与下次检查时间。默认每 3 秒检查，串行启动备忘识别，不阻塞等待网络；新条目和显式补处理每批最多加入 100 条，排队检查只读取必要元数据，不反复加载所有原文历史。

识别请求失败后分别等待约 30 秒、2 分钟，最多 3 次；网关自身的重试可能增加单次尝试的耗时。达到上限留待确认，可以明确重试。新原文在离线状态照常保存。重启和休眠恢复按已保存规则补处理；未完成识别的结果不能直接信任，重新识别后再判断。彻底退出期间没有进程处理请求，下次打开继续。

修改原文、移入回收站、手动归档、停止单条或保存新规则都会使旧处理失效。保存新规则会取消旧规则排队/运行中的条目，需要时按新规则重试；关闭后再次启用只自动处理新的修订，停用期间的记录须明确补处理。模型、供应商及密钥配置在请求后变化也拒绝自动写入。异步识别继续持有数据目录工作锁，退出先停队列再取消识别，避免旧请求回写其他目录。

归档和队列完成标记在同一 SQLite 事务中提交，事务故障不留下半份知识、任务或来源。识别请求在崩溃后可能再次调用供应商，产物则由修订身份、原有归档记录和事务去重保证不重复。

## 开源检索与选择

按直接使用、迁移、修改、自写的顺序比较：

- [sqlite-job-queue](https://github.com/rohit-jsfreaky/sqlite-job-queue)提供 Node/SQLite 持久任务、退避和失败队列参考。其独立队列/连接无法直接把本项目知识、任务、来源和完成标记纳入同一既有事务；不引入另一套数据库或通用作业执行面。本批直接复用项目已有 SQLite、识别状态机、生命周期/工作锁、任务与冲突服务，新增的只有备忘规则协调。
- [Memos 社区讨论 #5833](https://github.com/orgs/usememos/discussions/5833)用于核对启停范围、供应商选择、明确外发和保留派生结果控制等交互需求，不把讨论当作现成可用的自动归档实现。
- [Chrono](https://github.com/wanasit/chrono)的中文支持仍属于部分支持，不能据此接受课程相对时间。本批直接复用已安装 Temporal 做确定日期/钟点验证，复杂表达回到现有审核路径；不引入新解析依赖或拷贝外部代码。

沿用现有浅色主题、字体、折叠控件和双栏备忘页面；规则默认折叠，当前条目的处理状态直接可见，不改全局导航或快捷栏。
