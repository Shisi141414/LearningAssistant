# 开发路线图

> 版本：v0.2（2026-11-11）· 初稿：claude · 本次调整：codex · 原则：每期结束都有可验证的使用闭环

## 当前状态与下一轮执行顺序

2026-11-11 后续更新：R0 代码修复与回归检查已完成，详见 [构建记录](06-build-progress-2026-11-11.md)。以下段落保留初始体检基线；真实课堂/硬件验收仍待进行，下一批推进 R1 材料基础。

已实现 M0 的主要界面和 M1a 管线；不等于整体验收完成。2026-11-11 类型检查、三组冒烟测试、构建和隔离运行检查通过，但仍有对话显示、数据迁移与流式保存问题，详见 [体检报告](05-health-check-2026-11-11.md)。知识网络、知识库、习题库和复习页当前仍为占位；项目、日程、备忘尚未实现。

以下 R0–R6 是本次重新安排的**执行顺序**，M0–M5 保留原功能分组，避免把旧阶段名误当作完成标志。教材导入从原 M3 提前，支撑用户优先提出的课堂联动；自动分类与排程在基础实体可用后接入。细节、数据边界与场景验收见 [扩展规格](04-product-expansion.md)。

| 顺序 | 范围与依赖 | 最小交付与验收 |
|------|------------|----------------|
| R0 可靠性与协作 | 开始新增业务前；对应体检 H01–H11 | 模型目录/压缩包排除 Git；对话首条响应可见；中止保留内容；迁移不覆盖已有库且失败可恢复；课堂结束保存尾句；针对确认缺陷补回归检查；完善其余可靠性问题 |
| R1 材料基础（提前 M3） | R0；稳定来源位置是后续前提 | 课件/讲义/教材导入，先验收 PDF、DOCX、PPTX，再验收 DOC/PPT 转换与扫描 OCR；按学科条目化、原件与版本保留、搜索回原位、导入进度/取消/重试；切块不乱序且携带稳定位置 |
| R2 教材课堂联动 v1 | R1 + M1a | 左半屏材料右半屏记录；课前开始点；课中手动校准、切换材料；段落与教材双向定位；注入附近教材上下文且保留原转写；重启后引用仍有效 |
| R3 知识引用与应用基础（M2 核心） | R1–R2 | 抽取/合并知识点、保留证据、笔记与材料定位关联、跨学科检索；先形成可用的列表与引用闭环，再增强图谱、预回答缓存和习题关联 |
| R4 项目管理 | R3；先定义统一任务模型 | 项目要求、计划书、版本化文档、里程碑、当前进度、阻塞与截止时间；任务引用知识点并展示学习/应用路径；至少一个跨学科项目完成双向回链验收 |
| R5 日程与可靠提醒（整合 M4） | R4 的任务模型；手动任务可先交付 | 统一项目/手动/作业/复习任务；区分截止时间与时间块；自动安排、依赖/冲突检查、锁定与撤销；通知持久化、去重、重启/休眠恢复；明确应用退出后的运行条件 |
| R6 备忘自动分流与课堂对齐增强 | 自动分流依赖 R3–R5，自动对齐依赖 R1–R2；两部分可分别交付 | 备忘先保存原文，再自动分类至已有知识库/日程，支持混合条目、去重、撤销、待整理箱与离线补处理；课堂自动估计教材位置并显示置信度，人工校准优先 |

备忘的“快速保存原文”入口可在 R4/R5 期间提前交付，但不把自动归档提前标为完成。图谱美化、外部同步、复杂数学工具和桌面小组件按原阶段保留，优先保证上述闭环。每批功能随附相应 migration、IPC、界面和有实际意义的验收，不先创建一批空页面宣称交付。

## M0 — 地基与核心闭环（原阶段目标）

**目标**：应用能跑起来，完成"配置 API → 与智能体对话 → 写笔记并标注"最小闭环。

| 任务 | 验收标准 |
|------|---------|
| 项目框架 | electron-vite + React + TS 启动无错；主/预加载/渲染三进程结构成型；better-sqlite3 经 @electron/rebuild 正常加载 |
| 数据库层 | schema v1 全部建表；迁移机制（PRAGMA user_version）工作；seed 预置学科与供应商预设 |
| API 配置（模块12） | 供应商 CRUD（名称/baseURL/上游格式/Key）；Key safeStorage 加密存储；连通性测试按钮；从 /models 导入模型；模型能力五字段（上下文/识图/速度/备注）可编辑；预设供应商（DeepSeek/Qwen/GLM/Kimi 等）一键添加 |
| 智能体对话（模块5基础） | 多会话管理；流式输出；中断生成；会话挂到学科；发送时可引用笔记段落作为上下文 |
| 笔记与标注（模块2基础+3） | 笔记 CRUD；段落级编辑（类型标记：定义/命题/例题/证明/解答/注意，分色显示）；整段"重点/疑问"标注 + 标注备注；原文/整理双字段存储与切换展示（M0 为手动编辑，M1 接 AI） |
| 灵感库（模块9） | 快速记录灵感条目，关联学科 |
| 活动管理（模块13，2026-11-10 补充需求） | 讲座/会议/讨论独立分组：活动 CRUD（标题/类型/日期/关联学科），笔记可挂活动，活动列表按日期倒序 |
| 全局快捷栏（模块9条） | 所有页面底部固定："询问智能体"输入框 + "重点" + "疑问"按钮；选中内容后可点击（M0：跳转对话页带上选中内容） |
| Git | 规范提交；推送到 GitHub |

**明确不做（M0）**：实时转写、图片上传、知识图谱、BlockNote 富文本（M0 段落用 textarea 级编辑，数据模型已为 BlockNote 预留）、预回答缓存、learnx、FSRS。

## M1 — 课堂模式（转写流水线）

**目标**：真实课堂可用的实时转写 + 段落整理。**本地优先**（用户确认）：转写默认走本地 Provider，完全离线可用。

**M1a 已实现（2026-11-10，真实课堂验收待完成）**：
- 课堂页：setup（挂学科/活动、ASR 就绪检查）→ live（转写流+partial 实时行、段落分色、双视图、段落级标注、手动转写输入——无引擎时降级手动模式，管线一致）
- 本地 ASR：sherpa-onnx-node（optionalDependencies，v2.0.1）+ 流式 zipformer；端点检测自动断句；热词表；麦克风采集（渲染进程 16k PCM → IPC 喂数）
- AI 整理管线：final 落段 → 自动 LLM 整理（分类 seg_type + 纠错 + LaTeX 规整，JSON 容错解析），失败回退原文（ADR-0 降级）
- 语音引擎设置卡（模型目录/热词/安装状态）+ 数据与存储卡（自定义存储位置、迁移、恢复默认）
- migration 003：app_config KV；引导配置 userData/app-config.json（数据目录存库外）

**M1b 待办**：
- ⚠️ Windows 真机验证：sherpa-onnx 2.0.1 API 兼容性、zipformer-transducer（热词）vs Paraformer（精度）实测、延迟调优
- 2-pass 精转修正（流式 partial + VAD 离线 final 替换，飞书妙记式，参考 cueflow #2150）
- 讯飞云端 Provider（Key 申请）
- 模型自动下载器（GitHub Release 拉取解压）
- 图片上传 + vision 模型识别归位
- 课堂页快速提问面板

## M2 — 知识网络与预回答

- 知识点抽取（LLM 从笔记段落抽取候选，用户确认入库）
- 图谱页（@xyflow/react）：节点=知识点，边=关系，跨学科边高亮
- 快速提问的**预回答缓存**：非课堂时段，根据课堂进展预生成 Q&A 池；课堂提问先命中缓存（语义检索，可用 sqlite-vec 或简单关键词，届时调研定案）
- 数学计算辅助：SymPy + Pyodide 技术验证（渲染进程 WASM，离线符号推导），集成到快速提问与习题解答验证；Wolfram API 作为联网时的 LLM math tool
- 课后完整音频二次精转（whisper.cpp 系，Buzz 同引擎；可选）

## M3 — 知识库与习题库

- 材料基础提前至 R1：覆盖课件、讲义、教材，支持 PDF、Word、PowerPoint；扫描 OCR、旧格式转换和复杂公式作为明确验收项，解析器以样例验证后决定
- 解析结果按学科条目化、贴标签、按章节索引、携带稳定来源位置，可被对话/课堂/项目引用；R2 实现教材与转写的课堂分屏联动
- 习题库 CRUD：题面/用户解答/标准答案/思路（结构化步骤）/错误点标记/无思路标记；关联知识点与教材位置
- 灵感库增强（关联知识点）
- R4 项目系统与上述知识、材料、习题共用引用，帮助在项目任务中使用所学；R6 备忘扩展保留现有灵感数据

## 里程碑间的工作约定

1. 修改前检查状态并 `git pull --ff-only`，保留他人未提交改动；协作细则见根目录 [AGENTS.md](../AGENTS.md)
2. 每批代码完成后运行相关测试 + typecheck + 构建，及时提交并 push；文档批次检查差异与链接。推送前检查远端新提交，禁止默认强推
3. 每期开始前：按 01-research.md 的"决策层级"复查选型是否过时（社区调研不是一次性的）
4. 破坏性 schema 变更走 migration，禁止改老 migration 文件
