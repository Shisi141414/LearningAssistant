# 笔记 AI 结构建议与审核（2026-11-12）

报告：codex

## 功能与使用

笔记统一文档和课堂右侧统一文档均新增“AI 整理建议”。选择模型及连续待整理范围，生成边界、类型、标题、证明/解答归属候选；核对后“采纳为新修订”，也可放弃、取消或重新生成。正文从已保存的整理稿按来源范围截取，模型不能补写、删减或重排正文。

原始口述、人工编辑的整理稿、模型出处、教材位置和旧修订保持可追溯。人工确认的条目、公式校正、配图、已有证明关系及含子项的章节受到保护。需要修改 AI 候选的标题、类型或归属时，可放弃后人工整理，或采纳后用现有编辑器调整；首版未加入候选内编辑。

每批最多 20 个连续条目、12000 UTF-16 字符、200 个来源片段，生成最多两分钟，输出最多 32768 字符。仅发送选中整理稿文字；不自动附送原始口述、其他条目、录音或密钥。模型仍按现有主进程供应商设置调用。

## 复用决策

构建前比较了 [Vercel AI SDK 的结构化输出实现](https://github.com/vercel/ai/blob/main/packages/ai/src/generate-object/generate-object.ts)、[LangGraph JS 的人工审核流程](https://github.com/langchain-ai/langgraphjs/blob/main/docs/docs/concepts/human_in_the_loop.md)，并检索了 [社区文档解析审核案例](https://www.reddit.com/r/LangChain/comments/1sly2f2/using_langgraph_to_build_a_humanintheloop/)。结构化输出解决字段约束，审核流程解决何时执行；本项目还必须验证来源恰好覆盖、保留人工修改和拒绝旧修订。

因此优先直接复用已有教材整理器的片段化、提示词、严格输出校验、结构状态构建、审核界面和 LLM 传输层；将其文档输入缩小为共有的 `sources/state`，同时支持教材与笔记。笔记任务保存和生命周期按已有材料建议服务迁移适配，保留两者的独立外键与修订检查。无需为一个候选生成步骤引入完整 Agent 工作流依赖；未复制第三方代码或新增依赖。

## 保存与并发边界

- 追加迁移 18，新增 `note_learning_suggestions`，关联笔记文档、生成基准修订及采纳后的修订。候选和错误持久化；新建候选不发布文档。
- 生成与采纳都检查最新笔记及来源；来源待同步或修订已经变化时拒绝。采纳、结构校验、修订保存、任务状态更新位于同一事务，不修改原始段落。
- 课堂打开 AI 面板时暂停自动应用文档更新，方便选范围和核对；课堂仍持续保存新段落。收起面板恢复跟随。期间保存的新来源会使旧候选失效，不能因界面暂时停留在旧文档就绕过检查。
- 实际采纳操作锁住阅读器的其他修改操作；固定历史修订不显示生成入口。切换到最新笔记后可继续整理。其他段落的人工作业也不能被旧候选覆盖。
- 同时最多一个笔记结构生成；取消/超时/失败不发布候选，失败错误隐藏密钥。应用退出中止任务，下次启动将中断任务标为可见的已取消状态，不自动重发。

从编程角度，模型只是提出一份“如何切分来源”的数据。程序验证数据是否合法，用户决定是否采用，数据库事务最后负责发布。这三个职责分开，便于替换模型而保持内容保护规则不变。

## 未完成范围

本批用受控模型验证管线和保护机制，未证明真实模型对整堂课、模糊口述或数学讲解的分类质量。模型无法替代错误转写校正；复杂公式和图文仍须核对，不能把候选审核等同于整书/整堂课理解完成。严格按整篇修订判断是否过期，长课堂持续追加时建议先暂停录入或课后整理；未实现保留新追加内容的候选重基。

后续 [笔记文档包首批](29-portable-notes.md)已补公开契约及固定修订导出；下一步接通独立导入、外部出处保留和重复保护，再按路线图推进项目、日程和备忘闭环。
