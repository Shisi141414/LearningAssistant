# 知识点与来源证据

> 2026-11-11 · 设计与报告：codex · R3 首批方案

## 复用和建模

复查 [Logseq 块引用](https://github.com/logseq/docs/blob/master/pages/Block%20Reference.md)、[块引用教程](https://github.com/logseq/docs/blob/master/pages/The%20basics%20of%20block%20references.md) 与 [W3C Web Annotation 的来源状态](https://www.w3.org/TR/annotation-model/#states)。前者提供以稳定标识引用、反向查找的交互参考，后者区分来源版本与选择位置。直接复用现有概念 ID/别名、不可变学习修订、来源范围、SQLite 事务及 Markdown/公式阅读，不迁移整个知识管理软件，也不引入另一套块存储或向量数据库。

我们的学习条目拆分/合并会保留部分 ID，故引用必须固定 **材料版本＋学习修订＋条目 ID**，不能只保存当前条目 ID。笔记段落是可变的，引用时由主进程读取已保存字段，核对界面请求的文字，保存引用快照与 SHA-256。后续修改/删除只改变状态提示，不悄悄替换证据。快照不是外部教材准确性或论证正确性的认证。

本批完成手动证据引用、新建知识点并引用的原子操作、来源双向浏览及跨学科筛选。AI 知识候选、同义实体合并、依赖图谱和项目应用仍是后续工作；名称命中仍保留为动态“提及”，不自动升级为证据。

## 数据和边界

- 证据指向已有知识点；角色为来源、定义、证明、例题、反例或应用，并可填写引用说明。角色由用户确认，不根据文字相邻或别名命中推断。
- 学习文档记录修订/条目和当时标题、正文、来源标签；数据库外键保护已有修订。历史修订和已归档材料仍可阅读、引用。
- 笔记区分原文/整理两个字段。创建时核对段落归属及请求文字与已保存文字一致；未保存草稿不可引用。原段落删除后引用仍可读，跳转关闭并明确标为来源已删除。
- 每个知识点最多 100 个证据，单次正文最多 40000 UTF-16 单元，每页 20 条。长正文须先拆分条目；不截断后伪称完整引用。
- 同一知识点、同一学习修订条目，或同一笔记字段同一文字，只创建一次引用；重复请求返回已有证据，保留原角色与说明。不同修订或不同笔记文字可以并存。新建知识点与引用在同一事务中，失败全部回滚。
- 移除引用只解除知识点联系，不删除原教材、笔记或修订。引用不自动改写概念释义，不发送云请求。

## 实施前界面

沿用现有学习材料与知识页：宋体正文、黑体条目标题、楷体证明；背景 #f7f7f5、正文 #1f2328、辅助 #6b7280、边线 #e5e5e0、操作 #4f46e5。学习条目与笔记阅读下提供折叠“知识证据”，可搜索已有知识点、选择角色、填写说明后引用；也可展开新建表单并原子保存。

知识详情先显示“已确认的来源证据”，再显示“材料与笔记中的提及”。证据展示来源名、固定修订/位置、引用正文、角色及状态，可打开引用时原位或移除联系。知识列表增加学科筛选；跨学科联系允许显式建立，来源学科始终保留。教材证据链接打开学习视图并选中固定修订/条目，不用模糊搜索当前正文定位。

## 验收计划

旧库升级和外键；主进程拒绝伪造正文/错误来源；新建知识点与证据事务回滚；重复引用不改旧说明；分页和容量；重新分类、拆分、AI 重整/新版本后历史证据稳定；笔记原文/整理区分、未保存/并发变更拒绝、修改/删除后快照保留；归档材料可读；真实 Electron 关联、新建、双向导航、历史只读、移除和重启保留；类型检查与生产构建。

## 交付与检查（2026-11-11）

schema v12 仅追加证据表及索引，保留原学习来源、历史修订、笔记、标注与课堂锚点。学习文档和笔记段落下展开“知识证据”，选择已有知识点及角色后保存，或显式新建知识点并一同引用；知识详情可读取、移除证据并打开原位。历史修订和归档材料只读，仍可引用。仅收录主进程读取的文字，不接受界面伪造正文。

`npm test` 通过：数据库/整理/分块冒烟、44 项逻辑回归、真实 Electron 界面与独立应用重启。新增 5 项逻辑测试覆盖 v11 升级、来源归属和正文校验、不可变快照、笔记两字段与并发变更、事务回滚、去重、每概念 100 条容量和每页 20 条；原有材料、课堂、概念与 AI 审核回归保留。界面测试操作了引用、新建、历史跳转、学科筛选、移除、未保存禁止引用、保存后状态刷新、删除后快照及超过 100 条的第二组精确定位；重启后确认历史正文与笔记快照散列不变。`npm run typecheck` 与生产构建通过。

测试发现并修复两个界面问题：条目编辑器与引用组件不能使用相同的 React 同级 key，否则修订后可能留下旧编辑器；笔记草稿转为已保存时，证据状态也必须刷新，不能只监听草稿文字变化。笔记保存回执更新已保存基准，同时保留期间继续输入的新草稿。

检查了固定历史条目和 1024 宽知识页的界面。测试使用隔离样例与本地模拟模型，没有向真实云模型发送材料；本批不变更解析/OCR/转换算法，未重新进行整本真实教材的内容质量验收。全文超过 40000 UTF-16 单元须先拆分；自动提及、手动角色和证据快照均不等于系统认证论证正确。

用户新增的课堂笔记统一内部格式与内部文档 PDF 导出已记录到格式规范、扩展规格和路线图，尚未构建。完成本批测试、提交与推送后按要求暂停，待用户说“继续”恢复。
